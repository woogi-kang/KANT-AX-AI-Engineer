diff란?

diff는 두 칸을 골라 나란히 놓고 비교해요

① 작업 폴더

무엇을 칠지 헷갈리면 먼저 git status를 봐요. 빨간 글씨면 git diff, 초록 글씨면 git diff --staged, 깨끗하면 git show를 써요. merge 전에는 받을 쪽을 앞에 써서 git diff main 브랜치이름이에요. 수업에서는 이 장을 띄워 두고 상황마다 학생이 명령을 말해 보게 하세요.

충돌 중에 git diff를 치면 충돌 난 부분만 diff --cc 모양으로 보여 줘요. 앞에 기호가 두 칸 붙는 건 두 브랜치와 각각 비교해서예요. 지금은 ++ 줄이 충돌 표시이고 그 사이 위아래가 양쪽 내용이라는 것만 기억하면 돼요. 푸는 순서는 03과 같아요.

실제 상황 2 · 커밋 전에 빠진 파일 찾기

커밋 전에 --stat으로 파일 목록부터 훑어요

고친 건 두 파일인데 하나뿐이에요

$ git diff --staged --stat

새 파일은 git diff에 안 나와서 놓치기 쉬워요. 커밋 전에 파일 개수를 세어 봐요.

커밋 직전에 git diff --staged --stat으로 들어갈 파일 목록을 보면 빠뜨린 파일을 찾아요. 회원가입 링크와 회원가입 파일을 같이 만들었는데 login.md만 add했어요. 파일 개수가 하나뿐이라 status를 보니 signup.md가 Untracked로 남아 있었어요. 다시 add하고 --stat으로 두 파일을 확인한 뒤 커밋했어요. status의 안내 줄과 On branch main 줄은 화면 때문에 뺐어요.
