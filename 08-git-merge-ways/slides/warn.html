6. 충돌과 주의

push한 브랜치는 rebase하지 않아요

$ git rebase main

$ git push origin feature/login-button

 ! [rejected] feature/login-button -> feature/login-button (non-fast-forward)

GitHub에는 옛 D, E가 있어요. 여기서 pull하면 같은 커밋이 기록에 두 번 들어가요.

A

9f452aa

B

6d19f01

d51d818

D

6a9792d

E

3573c9a

D'

a40dc47

E'

origin/feature/login-button

feature/login-button

◀ HEAD

feature/login-button을 이미 push한 뒤에 rebase했어요. 내 컴퓨터에는 D', E', GitHub에는 D, E가 있어서 push가 거절돼요. 힌트는 pull하라고 하지만, pull하면 D, E와 D', E'가 둘 다 기록에 들어가고 합치기 커밋까지 생겨요. 메시지가 같은 커밋이 두 쌍 보여서 기록을 읽기 어려워져요. rebase 출력 줄은 뺐어요. 강제로 덮어쓰는 방법도 있지만 팀원이 받아 간 커밋과 어긋나서 이 과정에서는 쓰지 않아요. 이 상태가 되면 더 치지 말고 강사에게 물어봐요. 규칙은 하나예요. rebase는 push 전, 나만 가진 커밋에만 써요. main처럼 같이 쓰는 브랜치에서는 rebase하지 않아요.
