5. 비교와 오류

값 넘기기 오류 두 가지: 쉼표가 빠졌거나 %s에 따옴표를 붙였어요

(MONTH): 쉼표가 없어서 튜플이 아니라 글자

~/sports-app $ uv run main.py

Traceback (most recent call last):

 File "/home/kim/sports-app/main.py", line 8, in

   <module>

   row = conn.execute(SQL, (MONTH)).fetchone()

         ~~~~~~~~~~~~^^^^^^^^^^^^^^

 …

TypeError: query parameters should be a sequence or a

   mapping, got str

튜플이 아니라 글자 str이 왔어요

고치기

(MONTH)

→

(MONTH,)

결과 (63,)

'%s': 따옴표 안에 넣음

~/sports-app $ uv run main.py

Traceback (most recent call last):

 File "/home/kim/sports-app/main.py", line 8, in

   <module>

   row = conn.execute(SQL, (MONTH,)).fetchone()

         ~~~~~~~~~~~~^^^^^^^^^^^^^^^

 …

psycopg.errors.IndeterminateDatatype: could not

   determine data type of parameter $1

고치기

= '%s'

→

= %s

따옴표는 psycopg가 붙여요

값을 넘길 때 나는 오류 두 가지예요. 첫째는 값 하나를 넘기면서 쉼표를 빼먹었을 때예요. (MONTH)는 괄호로 감싼 글자일 뿐이라서 TypeError가 나요. 끝에 got str, 글자가 왔다고 알려 줘요. (MONTH,)처럼 쉼표를 붙이면 (63,)이 나와요. 중간의 라이브러리 안쪽 줄은 길어서 점 세 개로 줄였어요. 둘째는 퍼센트 s를 작은따옴표로 감쌌을 때예요. SQL에서 글자에 따옴표를 붙이던 습관 때문에 자주 나요. 따옴표 안의 퍼센트 s는 값 자리로 쓰이지 못해서 could not determine data type 오류가 나요. 따옴표는 psycopg가 알아서 붙여 주니 퍼센트 s만 적어요. 실행 화면은 tools/demo.py로 실제 PostgreSQL 18과 psycopg 3을 실행해서 옮긴 결과예요.
