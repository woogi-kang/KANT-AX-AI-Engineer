conn = psycopg.connect(DSN)

conn.execute("UPDATE members SET phone = '010-1111-2222' WHERE member_id = 10")

conn.commit()

print("바꿨어요")

conn.close()

이 줄이 없으면 저장되지 않아요

conn.commit() 줄 없이 실행했을 때

kant_shop=# SELECT member_id, name, phone FROM members WHERE member_id = 10;

member_id |  name  | phone

-----------+--------+-------

       10 | 임준서 |

비어 있어요

conn.commit() 줄을 넣고 실행했을 때

kant_shop=# SELECT member_id, name, phone FROM members WHERE member_id = 10;

member_id |  name  |     phone

-----------+--------+---------------

       10 | 임준서 | 010-1111-2222

(1 row)

저장됐어요

commit 없이 close()로 닫으면 바꾼 것이 취소돼요. psql은 문장마다 바로 저장했지만, psycopg는 commit해야 저장해요.

그래서 연결은 with 블록으로 열어요. 블록이 끝날 때 저장과 닫기를 알아서 해요.

with 없이 연결해도 돼요. psycopg.connect(DSN)의 결과를 conn에 담고, 다 쓰면 conn.close()로 닫아요. 10번 회원 임준서 님의 비어 있는 전화번호를 UPDATE로 넣어 봤어요. 먼저 일곱째 줄 conn.commit()을 빼고 실행했어요. 왼쪽처럼 commit() 없이 닫으면 바꿨어요가 찍혀도 psql에서 보면 전화번호가 여전히 비어 있어요. 저장하지 않은 변경은 연결을 닫을 때 취소돼요. 오른쪽은 이 줄을 넣고 다시 실행한 결과예요. close() 전에 conn.commit()을 부르면 저장돼요. psql에서는 문장 하나를 치면 바로 저장됐어요. 자동 커밋이라고 해요. psycopg는 commit해야 저장한다는 점이 달라요. 이걸 잊기 쉬워서 연결은 with 블록으로 여는 걸 권해요. 실행 화면은 tools/demo.py로 실제 PostgreSQL 18과 psycopg 3을 실행해서 옮긴 결과예요.
