다시 찾음

$ git reflog

e73617d HEAD@{0}: reset: moving to HEAD~1

b81d4e2 HEAD@{1}: commit: feat: 실수한 커밋

e73617d HEAD@{2}: pull origin main: Fast-forward

3f9a2c1 HEAD@{3}: commit: feat: 끝인사 추가

$ git reset --hard b81d4e2

HEAD is now at b81d4e2 feat: 실수한 커밋

HEAD가 움직인 기록이 최신순으로 남아요.
reflog는 내 컴퓨터에만 있고 GitHub에는 없어요.

앞 장의 reset HEAD~1로 b81d4e2가 log에서 사라졌어요. 그래도 커밋은 바로 지워지지 않고 .git 안에 남아 있어요. reflog는 HEAD가 지나간 자리를 최신순으로 보여 주는 기록이라, reset 직전 커밋(HEAD@{1})의 해시를 찾을 수 있어요. 그 해시로 reset --hard 하면 main이 다시 그 커밋을 가리켜요. --hard는 작업 폴더의 고친 내용을 지우니, 실행 전에 git status로 남은 변경이 없는지 확인하세요. reflog 기록은 기본 90일 정도 지나면 정리돼요. clone 받은 팀원 컴퓨터에는 내 reflog가 없어요.
