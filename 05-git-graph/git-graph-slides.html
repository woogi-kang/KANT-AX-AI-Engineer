GitHub의 실제 main

팀원 lee가 올린 b9f30e5는 GitHub에만 있고 내 Git Graph에는 아직 없어요.

git fetch origin을 쳐야 내 컴퓨터로 받아지고 그림에 나타나요.

이름표가 main | origin 하나로 붙어 있어도 GitHub과 같다는 보장은 없어요. origin/main은 마지막으로 push하거나 fetch했을 때의 GitHub main 위치예요. 그 뒤에 팀원이 올린 커밋은 git fetch origin을 쳐야 내 컴퓨터로 받아지고 Git Graph에 나타나요. 02에서 git log --oneline과 git log --oneline origin/main을 따로 쳐서 비교했던 걸 Git Graph는 한 화면에 보여 줘요.

터미널에 남아야 오류가 났을 때 읽고 고칠 수 있어요.

명령은 터미널

확인은 Git Graph

Fetch 버튼 대신 git fetch origin

checkout, merge, reset은 Git Graph 메뉴 대신 터미널에 쳐요. 커밋 줄이나 이름표를 오른쪽 클릭하면 이런 메뉴가 나와요. 버튼 한 번에 reset이나 merge가 실행돼서 무엇이 바뀌었는지 놓치기 쉬워요. 그래서 수업에서는 명령을 터미널에 직접 치고, 친 결과가 맞는지 Git Graph로 확인하는 데만 써요. 잘못 눌렀다면 창을 닫지 말고 터미널에서 git status와 git log --oneline부터 봐요.

가장 흔한 건 1번이에요. 바탕화면이나 상위 폴더를 열면 Git 저장소를 못 찾아요. git init을 한 바로 그 폴더를 열어요. 2번은 큰 그림에서 본 대로 Git Graph가 GitHub에 직접 묻지 않기 때문이에요. 3번의 새로고침은 Git Graph 탭 오른쪽 위 둥근 화살표 아이콘이에요.

그림만 보고 다음에 칠 명령을 골라요

git pull origin main

main

origin

둘이 붙어 있어요

할 일 없음

위에 있는 쪽이 앞서요. main이 위면 push, origin/main이 위면 pull이에요.

origin/main이 안 움직였는데 팀원이 올렸다고 하면, 먼저 git fetch origin을 쳐서 그림을 새로 받아요.

main과 origin/main 중 위에 있는 쪽이 앞선 쪽이에요. 학생에게 먼저 그림만 보여 주고 무엇을 칠지 말하게 한 뒤 한 칸씩 답을 보여 주세요. main이 origin/main보다 위에 있으면 내 컴퓨터가 앞선 거라 push해요. origin/main이 위에 있으면 GitHub이 앞선 거라 pull해요. 둘이 붙어 있으면 할 일이 없어요.
