3. FROM에 넣는 임시 표

이 예제는 HAVING으로 써도 같은 6명이 나와요

kant_shop=# SELECT member_id, SUM(pay_amount) AS total_paid

kant_shop-# FROM enrollments

kant_shop-# GROUP BY member_id

kant_shop-# HAVING SUM(pay_amount) >= 600000

kant_shop-# ORDER BY total_paid DESC;

member_id | total_paid

-----------+------------

       16 |     745000

        3 |     740000

       26 |     705000

       17 |     630000

       39 |     615000

       11 |     610000

(6 rows)

39

FROM 서브쿼리 (앞 장)

SELECT *

FROM (

SELECT member_id,

SUM(pay_amount) AS total_paid

FROM enrollments

GROUP BY member_id

) AS paid

WHERE paid.total_paid >= 600000

ORDER BY paid.total_paid DESC;

이럴 때

쓰는 것

묶은 결과를 한 번 거르기만 해요

HAVING이 짧아요

묶은 결과로 또 계산하거나 다른 표와 JOIN해요

FROM 서브쿼리

앞 장의 FROM 서브쿼리는 39에서 배운 HAVING으로도 쓸 수 있어요. 오른쪽이 HAVING SUM(pay_amount) >= 600000으로 쓴 쿼리예요. 결과는 같은 6명이에요. 묶은 결과를 한 번 거르기만 할 때는 HAVING이 짧고 읽기 쉬워요. FROM 서브쿼리는 묶은 결과로 또 계산하거나, 앞 장처럼 다른 표와 JOIN할 때 써요. 다음 장에서 HAVING으로는 안 되고 FROM 서브쿼리로만 되는 예를 봐요. psql 화면은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
