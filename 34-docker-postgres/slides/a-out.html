3. 계정과 접속 방법

밖에서 5432번으로 붙으면 비밀번호를 물어요

docker run --rm -it --add-host host.docker.internal:host-gateway postgres:18 psql -h host.docker.internal -U postgres

잠깐 쓰고 지울
컨테이너 하나 더

이 이름을 쓰게 해 줘요
(Mac, Windows는 없어도 돼요)

psql이 들어 있는 이미지

내 컴퓨터 5432번으로 접속

~ $ docker run … psql -h host.docker.internal -U postgres

Password for user postgres:

postgres=# \conninfo

          Connection Information

     Parameter       |        Value

----------------------+----------------------

Host                 | host.docker.internal

Server Port          | 5432

Password Used        | true

…

cafe1234를 쳤어요 (화면엔 안 보여요)

~ $ docker run … -U postgres

Password for user postgres:

psql: error: connection to server at

"host.docker.internal" (172.17.0.1), port 5432

failed: FATAL:  password authentication failed for

user "postgres"

cafe123

나중에 파이썬 앱도 이렇게 밖에서 5432번으로 붙어요. 그때 비밀번호가 필요해요.

밖에서 5432번으로 붙으면 비밀번호를 물어요. 컨테이너 밖의 프로그램이 붙는 모습을 보려고, psql이 들어 있는 postgres:18 이미지로 컨테이너를 하나 더 켜서 내 컴퓨터의 5432번으로 접속했어요. --rm은 나가면 이 컨테이너를 바로 지우는 옵션이에요. host.docker.internal은 컨테이너 안에서 내 컴퓨터를 부르는 이름이에요. Docker Desktop을 쓰는 Mac과 Windows는 이 이름을 알아서 쓸 수 있고, --add-host 부분은 리눅스에서 이 이름을 쓰게 해 줘요. 이번에는 Password for user postgres:로 비밀번호를 물어요. cafe1234를 치면 화면에는 안 보이지만 들어가져요. 백슬래시 conninfo의 Password Used가 true예요. 오른쪽은 cafe123으로 하나 빠뜨려 친 결과예요. password authentication failed, 비밀번호가 틀렸다는 오류예요. 나중에 파이썬 앱이 데이터베이스에 붙을 때도 이렇게 밖에서 5432번으로 붙어서, 그때 -e로 정한 비밀번호가 필요해요. 이 장은 따라 치지 않고 보기만 해도 돼요. 출력은 리눅스에서 만들었고, 백슬래시 conninfo 결과는 필요한 줄만 옮겼어요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
