6. 실제 상황 예제

compose down 하고 다음 날 up 해도 어제 주문이 남아 있어요

1. 문 닫을 때

~/cafe-pg $ docker compose down

[+] down 2/2

✔ Container cafe-pg-pg-1  Removed   0.2s

✔ Network cafe-pg_default Removed   0.2s

~/cafe-pg $ docker volume ls

DRIVER    VOLUME NAME

local     cafe-pg_pg-data

볼륨은 남아요

2. 다음 날 문 열 때

~/cafe-pg $ docker compose up -d

[+] up 2/2

✔ Network cafe-pg_default Created   0.0s

✔ Container cafe-pg-pg-1  Started   0.2s

~/cafe-pg $ docker compose exec pg psql -U postgres -d cafe

cafe=# INSERT INTO orders VALUES (3, 'cake', 1);

INSERT 0 1

cafe=# SELECT * FROM orders;

id |   menu    | qty

----+-----------+-----

 1 | latte     |   2

 2 | americano |   1

 3 | cake      |   1

(3 rows)

down은 컨테이너와 네트워크만 지워요. 볼륨을 지우는 down -v는 연습을 끝낼 때만 쳐요.

compose down 하고 다음 날 up 해도 어제 주문이 남아 있어요. 카페 문을 닫는다고 생각해 봐요. 4파트에서 주문 두 개를 넣은 ~/cafe-pg에서 docker compose down을 치면 컨테이너와 네트워크가 지워져요. docker volume ls로 보면 cafe-pg_pg-data 볼륨은 그대로 남아 있어요. 다음 날 docker compose up -d로 다시 열고 들어가서, 오늘 첫 주문인 케이크 하나를 넣었어요. SELECT로 보면 어제 넣은 1번, 2번 주문 아래에 오늘 넣은 3번이 붙어 있어요. 볼륨을 지우는 docker compose down -v는 연습을 다 끝내고 정리할 때만 쳐요. 데이터가 같이 사라져요. compose 진행 줄은 가운데 빈칸을 줄였어요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
