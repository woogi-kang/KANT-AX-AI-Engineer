주문 2개

컨테이너를 지우면 그 안의 데이터 폴더도 같이 지워져요.

새로 켠 pg에는 처음부터 있던 postgres 데이터베이스만 있어요.

볼륨 없이 켠 컨테이너를 지우면 데이터베이스도 같이 사라져요. 왼쪽은 2파트에서 한 대로 shop 데이터베이스와 orders 표를 만들고 주문 두 개를 넣은 모습이에요. 오른쪽에서 pg를 docker stop, docker rm으로 지우고, 같은 docker run 명령으로 다시 켰어요. -d shop으로 들어가려 하면 database shop does not exist, shop이라는 데이터베이스가 없다는 오류가 나요. 표와 주문뿐 아니라 데이터베이스까지 통째로 사라졌어요. 새 컨테이너에는 처음부터 있던 postgres 데이터베이스만 있어요. 실제 카페라면 하루 주문이 다 날아간 거예요. 33 MySQL에서 본 것과 같은 일이에요. 왼쪽 CREATE TABLE의 열 목록과 오른쪽 docker run의 옵션은 앞과 같아서 …로 줄였어요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
