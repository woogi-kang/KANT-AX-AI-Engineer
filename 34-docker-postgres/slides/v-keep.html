4. 볼륨과 compose

-v pg-data:/var/lib/postgresql을 붙이면 지웠다 켜도 남아요

~ $ docker run -d --name pg -e POSTGRES_PASSWORD=cafe1234 … -v pg-data:/var/lib/postgresql postgres:18

fd1395c21f5b…

~ $ docker exec -it pg psql -U postgres

postgres=# CREATE DATABASE shop;

CREATE DATABASE

postgres=# \c shop

You are now connected to database "shop" as user "postgres".

shop=# CREATE TABLE orders (…);

CREATE TABLE

shop=# INSERT INTO orders VALUES (1, 'latte', 2);

INSERT 0 1

shop=# INSERT INTO orders VALUES (2, 'americano', 1);

INSERT 0 1

~ $ docker stop pg

pg

~ $ docker rm pg

~ $ docker volume ls

~ $ docker exec -it pg psql -U postgres -d shop

shop=# SELECT * FROM orders;

 2 | americano |   1

(2 rows)

새 컨테이너지만 pg-data의 데이터를 그대로 읽었어요.

-v pg-data:/var/lib/postgresql을 붙이면 지웠다 켜도 남아요. 왼쪽은 볼륨을 붙여 켠 pg에 shop 데이터베이스와 orders 표를 만들고 주문 두 개를 넣은 뒤, docker stop과 docker rm으로 지운 모습이에요. docker volume ls로 보면 컨테이너는 지웠지만 pg-data 볼륨은 남아 있어요. 오른쪽은 같은 명령으로 다시 켠 모습이에요. logs 첫 줄에 Skipping initialization이 보여요. 데이터 폴더에 이미 데이터베이스가 있어서 처음 준비를 건너뛰었다는 뜻이에요. -d shop으로 들어가 SELECT를 치면 주문 두 개가 그대로 나와요. 컨테이너는 새로 만들었지만 데이터는 붕어빵 밖 보관함인 pg-data에 있었기 때문이에요. 오른쪽 docker run은 왼쪽과 같은 옵션이라 가운데를 …로 줄였고, logs도 첫 줄만 옮겼어요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
