3. 계정과 접속 방법

bash로 들어가서 psql을 쳐도 돼요. 안에서는 비밀번호를 안 물어요

~ $ docker exec -it pg bash

root@b0771208641d:/# psql -U postgres

postgres=# \q

root@b0771208641d:/# psql -U postgres -h localhost

postgres=# \conninfo

     Connection Information

     Parameter       |   Value

----------------------+-----------

Host                 | localhost

Password Used        | false

…

postgres=# \q

root@b0771208641d:/# exit

exit

비밀번호 안 물어요

-h localhost도 그대로

컨테이너 안에서 오는 접속은 믿고 들여보내요.

공식 이미지가 그렇게 설정해 둬요. 이걸 trust라고 불러요.

root@…:/#는 컨테이너 안 bash예요.

psql을 나와도 아직 컨테이너 안이에요. exit로 내 터미널에 돌아와요.

bash로 들어가서 psql을 쳐도 돼요. 30에서처럼 docker exec -it pg bash로 컨테이너 안에 먼저 들어가면 표시가 root@컨테이너ID:/#로 바뀌어요. 여기서 psql -U postgres를 치면 앞에서 본 것과 같은 psql이 열려요. 비밀번호는 묻지 않아요. -h localhost를 붙여서 주소로 접속해도 마찬가지예요. 백슬래시 conninfo의 Password Used가 false예요. 공식 이미지는 컨테이너 안에서 오는 접속을 믿고 들여보내게 설정해 둬요. 이걸 trust라고 불러요. 33 MySQL은 안에서도 -p로 비밀번호를 물었는데, 여기가 달라요. 백슬래시 q로 psql을 나와도 아직 컨테이너 안 bash예요. exit를 쳐야 내 터미널로 돌아와요. psql이 시작할 때 찍는 버전과 도움말 두 줄은 앞 장과 같아서 뺐고, 백슬래시 conninfo 결과는 필요한 줄만 옮겼어요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
