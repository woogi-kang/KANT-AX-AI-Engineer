~ $ docker stop pg

initialization

볼륨은 그대로

~ $ docker run … psql -h host.docker.internal -U postgres

Password for user postgres:

~ $ docker run … -U postgres -d shop

Password for user postgres:

shop=# SELECT * FROM orders;

id |   menu    | qty

 1 | latte     |   2

 2 | americano |   1

(2 rows)

처음 비밀번호 cafe1234

POSTGRES_로 시작하는 -e는 데이터 폴더가 비어 있을 때 한 번만 읽어요.

처음부터 다시 하려면 docker volume rm pg-data로 볼륨까지 지워요. 넣어 둔 데이터도 같이 지워져요.

볼륨에 데이터가 있으면 바꾼 비밀번호는 무시돼요. 4파트의 pg를 지우고, 같은 pg-data 볼륨을 붙인 채 POSTGRES_PASSWORD만 new5678로 바꿔 다시 켰어요. logs에 Skipping initialization이 보여요. 데이터 폴더에 이미 데이터베이스가 있어서 처음 준비를 건너뛰었다는 뜻이에요. 비밀번호를 정하는 일도 그 처음 준비 안에 있어서, 이번 -e는 쓰이지 않았어요. 오른쪽 위처럼 밖에서 new5678로 들어가면 password authentication failed가 나요. 처음에 정한 cafe1234로 들어가면 shop의 주문 두 개가 그대로 보여요. POSTGRES_USER, POSTGRES_DB도 똑같이 처음 한 번만 읽어요. 33 MySQL의 MYSQL_ROOT_PASSWORD도 같은 함정이 있었어요. 처음부터 다시 하고 싶으면 docker volume rm pg-data로 볼륨까지 지워요. 넣어 둔 데이터도 같이 사라지니 연습용일 때만 해요. 비밀번호를 SQL로 바꾸는 방법도 있지만 이 챕터에서는 다루지 않아요. 오른쪽 접속 명령은 3파트와 같아서 앞부분을 …로 줄였어요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
