3. 계정과 접속 방법

관리자는 =#, 일반 계정은 =>로 표시가 달라요

~ $ docker exec -it pg psql -U postgres

postgres=# CREATE USER app WITH PASSWORD 'app1234';

CREATE ROLE

postgres=# \du

                            List of roles

Role name |                         Attributes

-----------+------------------------------------------------------------

app       |

postgres  | Superuser, Create role, Create DB, Replication, Bypass RLS

권한 없음

관리자 (Superuser)

~ $ docker exec -it pg psql -U app -d postgres

postgres=> CREATE DATABASE test;

ERROR:  permission denied to create database

만들 권한이 없어요

앱이 쓸 계정은 관리자 대신 일반 계정으로 만들어요. 실수로 데이터베이스를 지우지 못해요.

관리자는 =#, 일반 계정은 =>로 표시가 달라요. postgres로 들어가서 CREATE USER로 계정 app을 만들었어요. WITH PASSWORD 뒤에 비밀번호를 작은따옴표로 적어요. PostgreSQL은 계정을 role이라고 불러서 CREATE ROLE이라고 답해요. 백슬래시 du로 계정 목록을 보면 postgres에는 Superuser, 관리자 표시가 붙어 있고 app은 비어 있어요. 아래는 app으로 들어간 모습이에요. 표시 끝이 =#이 아니라 =>예요. 관리자가 아니라는 뜻이에요. 여기서 CREATE DATABASE를 치면 permission denied, 권한이 없다는 오류가 나요. 실제 앱이 데이터베이스에 붙을 때는 이렇게 권한을 줄인 계정을 써요. 실수로 데이터베이스를 지우는 일을 막아 줘요. 일반 계정에 표를 쓸 권한을 주는 법은 다음에 배워요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
