개발 도구는 대부분 터미널에서 실행해요. 그래서 폴더를 글자로 다루는 법부터 익혀요.

Finder나 파일 탐색기에서 보던 폴더를 글자로 보는 창이 터미널이에요. Mac은 터미널 앱, Windows는 Git을 설치할 때 같이 깔린 Git Bash를 열어요. 둘 다 오늘 배우는 명령이 똑같이 동작해요.

프롬프트에 현재 위치가 보여요

kim@laptop:~/kant$

컴퓨터 이름

입력 자리

kim@MacBook kant %

Windows Git Bash

kim@DESKTOP MINGW64 ~/kant
$

이 자료에서는

~/kant $

프롬프트는 명령을 기다리는 줄이에요. 컴퓨터마다 모양은 달라도 현재 위치가 꼭 들어 있어요. $ 뒤에 명령을 쳐요. 이 자료에서는 화면을 아끼려고 현재 위치와 $ 만 남긴 짧은 모양으로 보여 줘요. Mac은 맨 끝이 $ 대신 % 예요. 자료의 명령을 따라 칠 때 $ 는 치지 않아요.

.md 파일은 글자만 든 텍스트 파일이에요. 폴더마다 있는 README.md도 마크다운이에요.

`

백틱은 한글 키보드에서 숫자 1 왼쪽의 ₩ 키예요. 한/영을 영문으로 바꾸고 누르면 ` 가 나와요.

md는 Markdown의 줄임말이에요. 왼쪽처럼 기호를 섞어 쓰면 GitHub이나 VS Code 미리보기에서 오른쪽처럼 보여요. # 하나는 큰 제목, ## 두 개는 작은 제목이에요. - 로 시작하면 목록, 별표 두 개로 감싸면 굵게예요. 명령어는 백틱 세 개로 위아래를 감싸요. 첫 줄 백틱 뒤에 bash나 shell처럼 언어 이름을 적으면 GitHub이 색을 입혀 줘요. 백틱은 한글 키보드에서 숫자 1 왼쪽 ₩ 키를 영문 상태로 누르면 나와요. 한글 상태면 ₩가 찍혀요. [보일 글자](주소)는 누르면 그 주소로 가는 링크예요. 기호 뒤에 띄어쓰기를 한 칸 꼭 넣어요. VS Code에서는 .md 파일을 열고 Cmd+Shift+V (Windows는 Ctrl+Shift+V)를 누르면 미리보기가 열려요.

rm -rf는 -r과 -f를 합친 거예요. -f가 붙으면 없는 파일을 지워도 에러가 나지 않고, 지우기 어려운 파일도 묻지 않고 지워요. 그래서 실수해도 아무 신호가 없어요. 개발하다 보면 node_modules 같은 큰 폴더를 지울 때 자주 써요. 쓰기 전에 pwd와 ls로 위치와 이름을 꼭 확인해요.

rm -rf를 치기 전에는
한 번 멈춰요

아래 명령은 절대 치지 않아요.

rm -rf ~

내 홈 폴더 전부가 사라져요

rm -rf /

컴퓨터 전체가 사라져요

rm -rf *

지금 폴더 안 전부가 사라져요

-f 때문에 rm -rf는 확인도 묻지 않고 에러도 알려 주지 않아요. 경로에 띄어쓰기 하나만 잘못 들어가도 엉뚱한 폴더가 지워져요. 예를 들어 rm -rf old /는 old와 맨 위 폴더 / 를 따로 지우라는 뜻이 돼요. 인터넷에서 본 rm -rf 명령을 그대로 복사해 붙이지 않아요. 치기 전에 pwd로 위치를, ls로 지울 이름을 확인해요. * 는 지금 폴더의 모든 이름을 뜻하는 기호예요.
