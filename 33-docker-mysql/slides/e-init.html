6. 실제 상황 예제

예제 2 · 처음 켤 때 메뉴 표를 SQL 파일로 채워요

~/cafe-db/init/menu.sql

CREATE TABLE menu (id INT PRIMARY KEY, name VARCHAR(20), price INT);

INSERT INTO menu VALUES (1, 'americano', 4000);

INSERT INTO menu VALUES (2, 'latte', 4500);

INSERT INTO menu VALUES (3, 'cake', 5000);

compose.yaml

volumes:

- cafe-data:/var/lib/mysql

- ./init:/docker-entrypoint-initdb.d

./init 폴더의 .sql 파일은 볼륨이 빈 채로 처음 켤 때 한 번만 실행돼요.

~/cafe-db $ docker compose down -v

…

~/cafe-db $ docker compose up -d

…

~/cafe-db $ docker compose logs db

…

… /usr/local/bin/docker-entrypoint.sh: running /docker-entrypoint-initdb.d/menu.sql

…

~/cafe-db $ docker compose exec db mysql -u root -p cafe

…

 

mysql> SELECT * FROM menu;

+----+-----------+-------+

| id | name      | price |

+----+-----------+-------+

|  1 | americano |  4000 |

|  2 | latte     |  4500 |

|  3 | cake      |  5000 |

+----+-----------+-------+

3 rows in set (0.00 sec)

볼륨까지 지워요

볼륨이 남아 있으면 안 돌아요

예제 1의 볼륨에서 up만 했더니 SHOW TABLES;에 orders만 있었어요. 그래서 down -v로 볼륨을 지우고 켰어요. 쌓인 주문도 같이 지워져요.

새 팀원도 git clone 뒤 up -d 한 번이면 같은 메뉴 표를 받아요.

예제 2예요. 새로 켤 때마다 메뉴 표를 손으로 만들기 번거로워서 SQL 파일로 적어 뒀어요. init 폴더의 menu.sql에 CREATE TABLE과 INSERT 세 줄을 적었어요. compose.yaml의 volumes에 ./init 폴더를 /docker-entrypoint-initdb.d에 연결하는 줄을 더해요. mysql 이미지는 처음 켤 때 이 폴더의 .sql 파일을 한 번 실행해 줘요. 주의할 점이 있어요. 앞 장의 함정처럼 볼륨에 데이터가 이미 있으면 처음 준비를 건너뛰어서 이 파일도 안 돌아요. 실제로 예제 1의 볼륨으로 켰더니 표가 orders뿐이었어요. 그래서 docker compose down -v로 볼륨까지 지우고 다시 켰어요. -v를 붙이면 쌓인 주문도 같이 지워지니 연습할 때만 써요. logs에 menu.sql을 실행했다는 줄이 보이고, SELECT로 메뉴 세 개가 나와요. 이 폴더를 GitHub에 올려 두면 새 팀원도 up -d 한 번으로 같은 메뉴 표를 받아요. 터미널 출력은 tools/demo.py로 실제 Docker와 MySQL을 실행한 결과예요.
