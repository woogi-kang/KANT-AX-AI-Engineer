4. 볼륨과 compose

-v cafe-data:/var/lib/mysql을 붙이면 지웠다 켜도 남아요

docker run … -p 3306:3306 -v cafe-data:/var/lib/mysql mysql:8.4

이름 있는 볼륨을 MySQL 데이터 폴더에

~ $ docker run … -v cafe-data:/var/lib/mysql mysql:8.4

13cac4776b85…

~ $ docker exec -it db mysql -u root -p cafe

…

mysql> CREATE TABLE orders (…);

Query OK, 0 rows affected

mysql> INSERT INTO orders VALUES (1, 'latte', 2);

Query OK, 1 row affected (0.01 sec)

~ $ docker stop db

db

~ $ docker rm db

db

주문을 넣고 컨테이너를 지워요

~ $ docker run … -v cafe-data:/var/lib/mysql mysql:8.4

501e0baabb23…

~ $ docker exec -it db mysql -u root -p cafe

…

 

mysql> SELECT * FROM orders;

+----+-------+------+

| id | menu  | qty  |

+----+-------+------+

|  1 | latte |    2 |

+----+-------+------+

1 row in set (0.00 sec)

같은 볼륨으로 다시 켜면 주문이 그대로예요

-v cafe-data:/var/lib/mysql을 붙이면 지웠다 켜도 남아요. 왼쪽은 볼륨을 붙여 켠 db에 표를 만들고 주문 하나를 넣은 뒤, docker stop과 docker rm으로 지운 모습이에요. 오른쪽은 같은 명령으로 다시 켜서 SELECT를 친 결과예요. 이번에는 오류 없이 1번 주문 latte 2잔이 그대로 나와요. 컨테이너는 새로 만들었지만 표는 cafe-data 볼륨에 있었기 때문이에요. 비밀번호와 데이터베이스를 만드는 처음 준비도 볼륨에 이미 있어서 다시 하지 않아요. 터미널의 docker run은 앞 장과 같은 옵션이라 가운데를 …로 줄였어요. 터미널 출력은 tools의 demo 스크립트로 실제 Docker와 MySQL을 실행한 결과예요.
