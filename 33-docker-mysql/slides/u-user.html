앱에는 root 대신 cafe 계정을 줘요. 실수해도 cafe 밖은 건드리지 못해요.

root는 서버 전체를 다루는 관리자예요. 앱이 쓸 계정은 따로 만들어 주는 게 좋아요. docker run에 -e MYSQL_USER=cafe와 -e MYSQL_PASSWORD=cafe5678을 더해 켜면, MySQL이 처음 준비할 때 cafe 사용자를 만들어요. cafe 사용자는 MYSQL_DATABASE로 만든 cafe 데이터베이스만 쓸 수 있어요. mysql -u cafe -p로 들어가 SHOW DATABASES를 치면 cafe와 MySQL 기본 둘만 보여요. 표는 만들 수 있지만 CREATE DATABASE는 ERROR 1044로 막혀요. 앱이 실수하거나 비밀번호가 새도 cafe 밖은 지킬 수 있어요. 따라 칠 때는 앞의 db를 docker stop, docker rm으로 지우고 -e 네 개로 다시 켜요. 이때 2파트에서 만든 표가 사라지는데, 왜 그런지는 4파트에서 봐요. 터미널 출력은 tools/demo.py로 실제 Docker와 MySQL을 실행한 결과예요.
