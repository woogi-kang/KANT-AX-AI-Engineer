6. 실제 상황 예제

예제 1 · 오늘 문을 닫고 내일 열어도 어제 주문이 남아요

월요일

~/cafe-db $ docker compose up -d

…

~/cafe-db $ docker compose exec db mysql -u root -p cafe

…

mysql> CREATE TABLE orders (…);

mysql> INSERT INTO orders VALUES (1, 'latte', 2);

mysql> INSERT INTO orders VALUES (2, 'cake', 1);

mysql> exit

~/cafe-db $ docker compose down

…

화요일

~/cafe-db $ docker compose up -d

…

~/cafe-db $ docker compose exec db mysql -u root -p cafe

…

 

mysql> INSERT INTO orders VALUES (3, 'americano', 3);

Query OK, 1 row affected (0.00 sec)

 

mysql> SELECT * FROM orders;

+----+-----------+------+

| id | menu      | qty  |

+----+-----------+------+

|  1 | latte     |    2 |

|  2 | cake      |    1 |

|  3 | americano |    3 |

+----+-----------+------+

3 rows in set (0.00 sec)

월요일 주문

오늘 주문

down은 컨테이너만 지우고 볼륨 cafe-db_cafe-data는 남겨 둬요.

예제 1이에요. compose로 켠 카페 DB에 월요일 주문 두 개를 넣고, 가게 문을 닫듯 docker compose down으로 껐어요. 화요일에 다시 up -d로 켜고 오늘 주문 하나를 더 넣은 뒤 SELECT를 쳤어요. 월요일 주문 두 개 아래에 오늘 주문이 붙어서 세 행이 나와요. down은 컨테이너와 네트워크만 지우고 볼륨은 남겨 둬요. 그래서 compose.yaml에 볼륨만 적어 두면 매일 껐다 켜도 데이터가 이어져요. 터미널은 앞에서 본 출력과 CREATE TABLE의 열 목록을 …로 줄였어요. 터미널 출력은 tools의 demo 스크립트로 실제 Docker와 MySQL을 실행한 결과예요.
