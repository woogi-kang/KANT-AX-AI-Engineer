볼륨이 남아 있으면 바꾼 비밀번호가 적용되지 않아요. 오류 메시지만 보면 원인을 찾기 어려운 함정이에요. 컨테이너를 지우고 -e로 새 비밀번호 new5678을 줘서 다시 켰어요. 그런데 cafe-data 볼륨은 그대로 붙였어요. 새 비밀번호로 들어가면 Access denied가 나와요. logs를 보면 처음 준비 단계 줄이 하나도 없어요. MySQL은 볼륨에 이미 데이터가 있으면 -e의 비밀번호와 데이터베이스 이름을 읽지 않고 건너뛰어요. 비밀번호도 예전 그대로예요. 예전 비밀번호로 들어가면 표가 그대로 있어요. 정말 처음부터 다시 하고 싶을 때만 docker volume rm으로 볼륨을 지워요. 그러면 표도 같이 지워져요. 터미널 출력은 tools의 demo 스크립트로 실제 Docker와 MySQL을 실행한 결과예요.
