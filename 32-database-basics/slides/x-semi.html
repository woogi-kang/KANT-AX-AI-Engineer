3. 자주 나는 오류

끝에 ;를 빠뜨리면 다음 줄을 기다려요

MySQL 8.4

mysql> SELECT * FROM orders

-> ;

+----+-----------+------+

| id | menu      | qty  |

+----+-----------+------+

|  1 | latte     |    2 |

|  2 | americano |    1 |

|  3 | cake      |    1 |

+----+-----------+------+

3 rows in set (0.00 sec)

PostgreSQL 18

cafe=# SELECT * FROM orders

cafe-# ;

id |   menu    | qty

----+-----------+-----

 1 | latte     |   2

 2 | americano |   1

 3 | cake      |   1

(3 rows)

->나 cafe-#가 보이면 서버가 문장 끝을 기다리는 중이에요. ;만 치고 Enter를 눌러요.

앞에서 친 줄과 합쳐서 한 문장으로 실행해요. CREATE TABLE을 줄 나눠 친 것도 같은 원리예요.

끝에 세미콜론을 빠뜨리면 다음 줄을 기다려요. SELECT 문장을 세미콜론 없이 치고 Enter를 눌렀어요. 오류가 나지 않고 프롬프트만 바뀌어요. MySQL은 화살표, PostgreSQL은 cafe 빼기 샵이에요. 서버가 문장이 아직 안 끝났다고 보고 다음 줄을 기다리는 거예요. 처음엔 멈춘 것처럼 보여서 당황하기 쉬워요. 세미콜론만 치고 Enter를 누르면 앞에서 친 줄과 합쳐서 실행해요. 2파트에서 CREATE TABLE을 여러 줄로 나눠 친 것도 같은 원리예요. SQL 출력은 tools/demo.py로 실제 MySQL 8.4와 PostgreSQL 18에서 실행한 결과예요.
