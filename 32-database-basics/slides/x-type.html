3. 자주 나는 오류

열 타입에 맞지 않는 값도 막아요

INT 열 qty에 글자 'many'

MySQL 8.4

mysql> INSERT INTO orders VALUES (4, 'tea', 'many');

ERROR 1366 (HY000): Incorrect integer value: 'many' for column 'qty' at row 1

PostgreSQL 18

cafe=# INSERT INTO orders VALUES (4, 'tea', 'many');

ERROR:  invalid input syntax for type integer: "many"

LINE 1: INSERT INTO orders VALUES (4, 'tea', 'many');

                                            ^

VARCHAR(20) 열 menu에 25자

MySQL 8.4

mysql> INSERT INTO orders VALUES (4, 'vanilla caramel macchiato', 1);

ERROR 1406 (22001): Data too long for column 'menu' at row 1

PostgreSQL 18

cafe=# INSERT INTO orders VALUES (4, 'vanilla caramel macchiato', 1);

ERROR:  value too long for type character varying(20)

열 타입에 맞지 않는 값도 막아요. 위는 정수만 받는 qty 열에 many라는 글자를 넣은 경우예요. MySQL은 Incorrect integer value, PostgreSQL은 invalid input syntax for type integer라고 해요. 둘 다 정수가 아니라는 뜻이에요. PostgreSQL은 LINE 줄 아래 꺾쇠로 문제가 된 자리를 짚어 줘요. 아래는 20자까지만 받는 menu 열에 25자짜리 메뉴 이름을 넣은 경우예요. Data too long, value too long 모두 너무 길다는 뜻이에요. 값을 고치거나, 표를 만들 때 VARCHAR의 숫자를 넉넉히 정해요. 파이썬 리스트였다면 아무 말 없이 들어갔을 값이에요. SQL 출력은 tools/demo.py로 실제 MySQL 8.4와 PostgreSQL 18에서 실행한 결과예요.
