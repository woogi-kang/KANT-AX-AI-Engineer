MySQL과 PostgreSQL은 둘 다 관계형이라서 오늘 배우는 낱말이 그대로 통해요.

서버 안에 데이터베이스가, 그 안에 표가 있어요. 서버 하나에 데이터베이스를 여러 개 만들 수 있어요. 보통 서비스나 가게마다 하나씩 만들어요. 오늘은 cafe 데이터베이스를 만들고, 그 안에 주문 표 orders를 둬요. 4파트에서는 메뉴 표 menu도 더해요. 오른쪽 점선 안은 서버가 처음부터 갖고 있는 데이터베이스예요. 서버가 스스로 쓰는 것이라 건드리지 않아요. MySQL과 PostgreSQL은 이름만 달라요. 파일로 치면 서버는 컴퓨터, 데이터베이스는 폴더, 표는 엑셀 파일, 행과 열은 시트 안의 칸이에요. 이름들은 두 서버의 데이터베이스 목록을 실제로 띄워서 옮겼어요. 다음 파트에서 이 구조를 SQL로 만들어요.

끝에 세미콜론을 빠뜨리면 다음 줄을 기다려요. SELECT 문장을 세미콜론 없이 치고 Enter를 눌렀어요. 오류가 나지 않고 프롬프트만 바뀌어요. MySQL은 화살표, PostgreSQL은 cafe 빼기 샵이에요. 서버가 문장이 아직 안 끝났다고 보고 다음 줄을 기다리는 거예요. 처음엔 멈춘 것처럼 보여서 당황하기 쉬워요. 세미콜론만 치고 Enter를 누르면 앞에서 친 줄과 합쳐서 실행해요. 2파트에서 CREATE TABLE을 여러 줄로 나눠 친 것도 같은 원리예요. SQL 출력은 tools/demo.py로 실제 MySQL 8.4와 PostgreSQL 18에서 실행한 결과예요.

3. 자주 나는 오류

글자 값에 작은따옴표를 빠뜨리면 열 이름으로 읽어요

MySQL 8.4

mysql> INSERT INTO orders VALUES (4, latte, 1);

ERROR 1054 (42S22): Unknown column 'latte' in 'field list'

PostgreSQL 18

cafe=# INSERT INTO orders VALUES (4, latte, 1);

ERROR:  column "latte" does not exist

LINE 1: INSERT INTO orders VALUES (4, latte, 1);

                                     ^

고친 문장

INSERT INTO orders VALUES (4, 'latte', 1);

따옴표가 없으면 latte를 열 이름으로 읽고, 그런 열이 없다고 해요. 숫자 값은 따옴표 없이 적어요.

글자 값에 작은따옴표를 빠뜨리면 열 이름으로 읽어요. latte를 따옴표 없이 적었어요. 서버는 따옴표 없는 낱말을 열 이름으로 읽어서, latte라는 열을 찾다가 없다고 알려 줘요. MySQL은 Unknown column, PostgreSQL은 column does not exist예요. 글자 값의 앞뒤에 작은따옴표를 붙이면 돼요. 파이썬처럼 큰따옴표를 쓰면 MySQL은 받아 주지만 PostgreSQL은 열 이름으로 읽어요. 두 서버에서 다 되도록 작은따옴표로 적어요. 숫자 값 4와 1은 따옴표 없이 적어요. SQL 출력은 tools/demo.py로 실제 MySQL 8.4와 PostgreSQL 18에서 실행한 결과예요.
