실습 1 · 주의

restore로 버린 줄은 되찾을 수 없어요

커밋하지 않은 변경은 Git에 기록이 없어요. reset과 revert는 커밋을 다뤄서 기록이 남지만, restore로 버린 줄은 휴지통에도 가지 않아요.

1

먼저 git diff로 봐요

사라질 줄을 눈으로 확인해요

git diff

2

남길 게 있으면 커밋부터 해요

커밋해 두면 나중에 되돌릴 수 있어요

git add 파일
git commit -m "..."

3

파일 이름을 꼭 적어요

점(.)을 쓰면 폴더 안 모든 파일의 변경을 한 번에 버려요

git restore login.md
git restore .

restore로 버린 변경은 되찾을 수 없어서, 버리기 전에 세 가지를 지켜요. 02에서 본 reflog도 커밋만 기억해서 여기엔 소용없어요. 먼저 git diff로 보고, 남길 줄이 있으면 커밋부터 하고, 파일 이름을 꼭 적어요. git restore . 처럼 점을 쓰면 폴더 안 모든 파일의 변경이 한 번에 사라져요.

pop은 서랍에서 꺼내 작업 폴더에 다시 얹고, 꺼낸 서랍은 지워요. Auto-merging은 받은 제목과 내 비밀번호 찾기를 Git이 알아서 합쳤다는 뜻이에요. 서로 다른 줄이라 충돌 없이 끝났어요. 마지막 Dropped 줄이 서랍에서 지웠다는 뜻이에요. 이제 하던 일을 마저 하고 add, commit, push해요.
