탈퇴, 상품 삭제, 같은 이메일도 규칙대로 처리돼요

kant_shop=# DELETE FROM product WHERE id = 2;

ERROR:  update or delete on table "product" violates foreign key constraint "cart_item_product_id_fkey" on table "cart_item"

DETAIL:  Key (id)=(2) is still referenced from table "cart_item".

kant_shop=# DELETE FROM member WHERE id = 1;

DELETE 1

kant_shop=# INSERT INTO member (name, email) VALUES ('park', 'lee@mail.com');

ERROR:  duplicate key value violates unique constraint "member_email_key"

DETAIL:  Key (email)=(lee@mail.com) already exists.

kant_shop=# UPDATE product SET stock = -1 WHERE id = 3;

ERROR:  new row for relation "product" violates check constraint "product_stock_check"

DETAIL:  Failing row contains (3, battery, 32000, -1).

SELECT로 보면 lee의 텀블러 한 줄만 남았어요. 새 회원 park이 lee와 같은 이메일로 가입하면 UNIQUE에, 재고를 -1로 바꾸면 CHECK에 걸려요. UPDATE도 INSERT처럼 문지기를 지나요. psql 화면은 tools/demo.py로 실제 postgres:18 컨테이너에서 실행한 결과예요.
