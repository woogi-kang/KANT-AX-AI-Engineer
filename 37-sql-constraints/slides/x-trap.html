6. 오류와 실제 상황

NULL은 UNIQUE, CHECK, DEFAULT를 그냥 지나가요

kant_shop=# CREATE TABLE member (

kant_shop(#  id INTEGER PRIMARY KEY,

kant_shop(#  email VARCHAR(50) UNIQUE,

kant_shop(#  points INTEGER DEFAULT 0 CHECK (points >= 0)

kant_shop(# );

CREATE TABLE

kant_shop=# INSERT INTO member VALUES (1, NULL, NULL), (2, NULL, NULL);

INSERT 0 2

kant_shop=# SELECT * FROM member;

id | email | points

----+-------+--------

 1 |       |

 2 |       |

(2 rows)

email NULL이 두 번 들어갔어요 (UNIQUE 통과)

points도 NULL, DEFAULT 0이 안 쓰이고 CHECK도 통과

kant_shop=# INSERT INTO member VALUES (3, 'kim@mail.com', DEFAULT);

INSERT 0 1

kant_shop=# SELECT * FROM member;

id |    email     | points

----+--------------+--------

 1 |              |

 2 |              |

 3 | kim@mail.com |      0

(3 rows)

값 자리에 DEFAULT를 쓰면 기본값

NULL은 값이 없다는 뜻이라서 규칙 몇 개를 그냥 지나가요. email에 UNIQUE가 있어도 NULL은 두 번 들어가요. 없는 값끼리는 겹친다고 보지 않아서예요. points에 NULL을 직접 적으면 DEFAULT 0이 쓰이지 않아요. DEFAULT는 열을 안 적었을 때만 쓰여요. CHECK (points >= 0)도 통과해요. NULL과 비교한 결과는 참도 거짓도 아니라서, CHECK는 거짓일 때만 막아요. 아래처럼 값 자리에 DEFAULT라고 적으면 기본값이 들어가요. 이 구멍을 막는 방법이 다음 장이에요. psql 화면은 tools/demo.py로 실제 postgres:18 컨테이너에서 실행한 결과예요.
