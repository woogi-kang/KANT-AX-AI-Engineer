6. 오류와 실제 상황

장바구니에 담을 때 규칙이 실수를 막아요

kant_shop=# INSERT INTO cart_item VALUES (1, 1, 1), (1, 2, 2);

INSERT 0 2

kant_shop=# INSERT INTO cart_item VALUES (1, 2, 1);

ERROR:  duplicate key value violates unique constraint "cart_item_pkey"

DETAIL:  Key (member_id, product_id)=(1, 2) already exists.

kant_shop=# UPDATE cart_item SET qty = qty + 1 WHERE member_id = 1 AND product_id = 2;

UPDATE 1

kant_shop=# INSERT INTO cart_item VALUES (1, 9, 1);

ERROR:  insert or update on table "cart_item" violates foreign key constraint "cart_item_product_id_fkey"

DETAIL:  Key (product_id)=(9) is not present in table "product".

kant_shop=# INSERT INTO cart_item VALUES (1, 3, 0);

ERROR:  new row for relation "cart_item" violates check constraint "cart_item_qty_check"

DETAIL:  Failing row contains (1, 3, 0).

kant_shop=# SELECT * FROM cart_item;

member_id | product_id | qty

-----------+------------+-----

        1 |          1 |   1

        1 |          2 |   3

(2 rows)

같은 상품을 또 담으면 막혀요

qty를 늘려요, 28의 get(product, 0) + qty

9번 상품은 없어요

0개는 못 담아요

product 표에 넣어 둔 28의 상품 (SELECT * FROM product 결과)

1 earphone 89,000원

2 tumbler 15,000원

3 battery 32,000원

4 mousepad 9,000원 품절

5 usb hub 30,000원

28의 상품 다섯 개를 product 표에 넣었어요. 이름은 psql 표가 줄이 맞게 영어로 바꿨어요. kim이 이어폰 하나와 텀블러 두 개를 담았어요. 텀블러를 하나 더 담으려고 INSERT를 또 치면 복합 기본 키에 걸려요. 28의 cart.py에서는 self.items.get(product, 0) + qty로 수량을 늘렸어요. 표에서도 같아요. UPDATE로 qty를 1 늘려요. 없는 9번 상품을 담으면 외래 키에, 0개를 담으면 CHECK에 걸려요. 파이썬 코드에서 if로 막던 실수를 표의 규칙이 막아요. 마지막 SELECT에 텀블러가 3개로 한 줄만 있어요. psql 화면은 tools/demo.py로 실제 postgres:18 컨테이너에서 실행한 결과예요.
