3. 기본 키와 자동 번호

번호 열을 따로 두면 UNIQUE (열, 열)로 쌍을 막아요

kant_shop=# CREATE TABLE cart_item (

kant_shop(#  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,

kant_shop(#  member_id INTEGER,

kant_shop(#  product_id INTEGER,

kant_shop(#  qty INTEGER NOT NULL,

kant_shop(#  UNIQUE (member_id, product_id)

kant_shop(# );

CREATE TABLE

kant_shop=# INSERT INTO cart_item (member_id, product_id, qty) VALUES (1, 1, 1), (1, 2, 2);

INSERT 0 2

kant_shop=# INSERT INTO cart_item (member_id, product_id, qty) VALUES (1, 1, 3);

ERROR:  duplicate key value violates unique constraint "cart_item_member_id_product_id_key"

DETAIL:  Key (member_id, product_id)=(1, 1) already exists.

kant_shop=# INSERT INTO cart_item (member_id, product_id, qty) VALUES (NULL, 1, 1), (NULL, 1, 1);

INSERT 0 2

kant_shop=# SELECT * FROM cart_item;

id | member_id | product_id | qty

----+-----------+------------+-----

 1 |         1 |          1 |   1

 2 |         1 |          2 |   2

 4 |           |          1 |   1

 5 |           |          1 |   1

(4 rows)

쌍이 겹치면 안 돼요

NULL이 든 쌍은 막지 않아요

kant_shop=# INSERT INTO order_item VALUES (NULL, 1, 1);

ERROR:  null value in column "order_id" of relation "order_item" violates not-null constraint

DETAIL:  Failing row contains (null, 1, 1).

복합 기본 키는 NULL을 막아요

같은 쌍 막기를 다르게 할 수도 있어요. 번호 열 id를 기본 키로 따로 두고, 쌍에는 UNIQUE (member_id, product_id)를 붙여요. 같은 회원이 같은 상품을 또 담으면 cart_item_member_id_product_id_key에 걸려요. 표 이름 뒤에 열 이름 두 개와 key를 이었어요. 다른 점은 NULL이에요. UNIQUE는 NULL이 든 쌍을 서로 다르다고 봐서 두 번 들어가요. 아래처럼 복합 기본 키는 NULL부터 막아요. 행을 따로 가리킬 번호가 필요하면 id와 복합 UNIQUE를, 쌍 자체가 행의 이름이면 복합 기본 키를 써요. 이때 UNIQUE 쪽 열에는 NOT NULL을 같이 붙여요. psql 화면은 tools/demo.py로 실제 postgres:18 컨테이너에서 실행한 결과예요.
