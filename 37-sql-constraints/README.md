# 37 · SQL 2 (제약 조건으로 표 설계하기)

## 학습 목표

- `NOT NULL`, `DEFAULT`, `UNIQUE`, `CHECK`를 열 뒤에 붙이고, 규칙에 걸린 `INSERT`의 오류를 읽어요.
- `CONSTRAINT 이름`으로 규칙에 이름을 붙이고, 이름을 안 붙였을 때 PostgreSQL이 짓는 이름(`_key`, `_check`, `_pkey`, `_fkey`)을 알아봐요.
- `PRIMARY KEY`가 `NOT NULL`과 `UNIQUE`를 합친 규칙이라는 것을 실제 오류로 확인해요.
- 번호를 자동으로 채우는 `SERIAL`과 `GENERATED ALWAYS AS IDENTITY`를 비교하고, 새 표는 `IDENTITY`로 만들어요.
- 열 두 개로 기본 키를 만들고(`PRIMARY KEY (a, b)`), 복합 `UNIQUE`와 다른 점을 말해요.
- `REFERENCES`로 표 두 개를 잇고, 부모 행을 지울 때 `RESTRICT`, `CASCADE`, `SET NULL` 중 하나를 골라요.
- `TRUNCATE 표 RESTART IDENTITY`로 표를 비우고 번호를 1부터 다시 세요. 외래 키로 이어진 표는 한 줄에 같이 적어요.
- `ALTER TABLE`로 만든 표에 규칙을 더하고 지워요.

## 핵심 개념

### 제약 조건은 표 앞의 문지기예요

`INSERT`로 들어오는 행과 `UPDATE`로 바뀌는 행은 모두 규칙을 지나요. 규칙에 걸린 행은 한 칸도 들어가지 않고 `ERROR`가 나요.

| 규칙 | 뜻 | 붙이는 자리 |
| --- | --- | --- |
| `NOT NULL` | 비우면 안 돼요 | 열 뒤 |
| `DEFAULT 값` | 안 적으면 이 값을 넣어요 | 열 뒤 |
| `UNIQUE` | 같은 값이 두 번 못 들어가요 | 열 뒤, 여러 열이면 표 끝 `UNIQUE (a, b)` |
| `CHECK (조건)` | 조건이 참인 값만 받아요 | 열 뒤, 열 두 개를 비교하면 표 끝 |
| `PRIMARY KEY` | `NOT NULL` + `UNIQUE`, 표에 하나 | 열 뒤, 여러 열이면 표 끝 `PRIMARY KEY (a, b)` |
| `REFERENCES 표 (열)` | 다른 표에 있는 값만 받아요(외래 키) | 열 뒤 |

### 오류에 나오는 규칙 이름

이름을 안 붙이면 PostgreSQL이 이렇게 지어요. `CONSTRAINT 이름 규칙`으로 직접 붙이면 오류에 그 이름이 나와요.

| 규칙 | 이름 | 예 |
| --- | --- | --- |
| `UNIQUE` | 표\_열\_key | `member_email_key` |
| `CHECK` | 표\_열\_check | `product_price_check` |
| `PRIMARY KEY` | 표\_pkey | `member_pkey` |
| `FOREIGN KEY` | 표\_열\_fkey | `orders_member_id_fkey` |
| `NOT NULL` | 이름 없음, 열 이름이 나와요 | `null value in column "name"` |

### 번호를 자동으로 채우는 세 가지

| | `SERIAL` | `GENERATED BY DEFAULT AS IDENTITY` | `GENERATED ALWAYS AS IDENTITY` |
| --- | --- | --- | --- |
| id 없이 `INSERT` | 1, 2, 3 차례로 | 1, 2, 3 차례로 | 1, 2, 3 차례로 |
| 번호를 직접 넣기 | 들어가요 | 들어가요 | `ERROR`로 막아요 |
| 직접 넣은 뒤 자동 번호 | 겹치면 `ERROR` | 겹치면 `ERROR` | 직접 못 넣어서 안 겹쳐요 |

새로 만드는 표의 번호 열은 `id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY`로 만들어요. 실패한 `INSERT`도 번호를 하나 써 버려서 번호 사이가 빌 수 있어요.

### 복합 기본 키와 복합 UNIQUE

| | `PRIMARY KEY (order_id, product_id)` | `id` 기본 키 + `UNIQUE (member_id, product_id)` |
| --- | --- | --- |
| 같은 쌍 두 번 | 막아요 | 막아요 |
| 쌍에 NULL | 막아요 | 들어가요(NULL끼리는 겹친다고 안 봐요) |
| 언제 | 쌍 자체가 행의 이름일 때 | 행마다 따로 번호가 필요할 때. 쌍의 열에 `NOT NULL`을 같이 붙여요 |

### 부모 행을 지울 때

| 외래 키 뒤에 | 부모 행을 지우면 |
| --- | --- |
| (안 적음) | 자식이 있으면 `DELETE`를 막아요 |
| `ON DELETE RESTRICT` | 자식이 있으면 `DELETE`를 막아요 |
| `ON DELETE CASCADE` | 자식 행도 같이 지워요 |
| `ON DELETE SET NULL` | 자식의 외래 키 칸을 NULL로 바꿔요 |

표는 부모부터 만들고, 자식부터 지워요.

### 행을 모두 지우는 두 가지

| 명령 | 지우는 것 | 다음 번호 |
| --- | --- | --- |
| `DELETE FROM 표;` | 행을 하나씩(`WHERE`로 고를 수 있어요) | 이어서 |
| `TRUNCATE 표;` | 표를 통째로 | 이어서 |
| `TRUNCATE 표 RESTART IDENTITY;` | 표를 통째로 | 1부터 |

외래 키로 이어진 표는 `TRUNCATE 자식, 부모`처럼 한 줄에 같이 적어요. 적는 순서는 상관없어요.

## 실습

출력은 `tools/demo.py`로 실제 `postgres:18`(18.7)을 실행한 결과예요. 시각은 내 화면과 달라요.

### 1. NOT NULL과 DEFAULT

```sql
CREATE TABLE member (
  id INTEGER,
  name VARCHAR(20) NOT NULL,
  points INTEGER DEFAULT 0,
  joined_at TIMESTAMPTZ DEFAULT now()
);
INSERT INTO member (id, points) VALUES (1, 100);
INSERT INTO member (id, name) VALUES (1, 'kim');
SELECT * FROM member;
\d member
```

이름을 빼면 이렇게 막혀요.

```
ERROR:  null value in column "name" of relation "member" violates not-null constraint
```

이름만 넣으면 `points`에 0, `joined_at`에 지금 시각(세계 표준시, `+00`)이 들어가요.

### 2. UNIQUE와 CHECK

```sql
DROP TABLE member;
CREATE TABLE member (
  id INTEGER,
  name VARCHAR(20) NOT NULL,
  email VARCHAR(50) UNIQUE
);
INSERT INTO member VALUES (1, 'kim', 'kim@mail.com');
INSERT INTO member VALUES (2, 'lee', 'kim@mail.com');
```

```
ERROR:  duplicate key value violates unique constraint "member_email_key"
DETAIL:  Key (email)=(kim@mail.com) already exists.
```

```sql
CREATE TABLE product (
  id INTEGER,
  name VARCHAR(20) NOT NULL,
  price INTEGER,
  sale_price INTEGER,
  CONSTRAINT price_positive CHECK (price > 0),
  CONSTRAINT sale_lower CHECK (sale_price < price)
);
INSERT INTO product VALUES (1, 'tumbler', 15000, 18000);
```

```
ERROR:  new row for relation "product" violates check constraint "sale_lower"
DETAIL:  Failing row contains (1, tumbler, 15000, 18000).
```

### 3. 기본 키와 자동 번호

```sql
DROP TABLE member;
DROP TABLE product;
CREATE TABLE product (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(20) NOT NULL,
  price INTEGER
);
INSERT INTO product (name, price) VALUES ('earphone', 89000), ('tumbler', 15000);
INSERT INTO product VALUES (3, 'battery', 32000);
SELECT * FROM product;
```

```
ERROR:  cannot insert a non-DEFAULT value into column "id"
DETAIL:  Column "id" is an identity column defined as GENERATED ALWAYS.
HINT:  Use OVERRIDING SYSTEM VALUE to override.
```

HINT의 `OVERRIDING SYSTEM VALUE`는 수업에서 쓰지 않아요. 번호 열은 `INSERT`에서 빼요.

```sql
CREATE TABLE order_item (
  order_id INTEGER,
  product_id INTEGER,
  qty INTEGER NOT NULL,
  PRIMARY KEY (order_id, product_id)
);
INSERT INTO order_item VALUES (1, 1, 1), (1, 2, 2), (2, 1, 1);
INSERT INTO order_item VALUES (1, 1, 5);
```

```
ERROR:  duplicate key value violates unique constraint "order_item_pkey"
DETAIL:  Key (order_id, product_id)=(1, 1) already exists.
```

### 4. 외래 키

```sql
DROP TABLE order_item;
DROP TABLE product;
CREATE TABLE member (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(20) NOT NULL
);
CREATE TABLE orders (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  member_id INTEGER REFERENCES member (id),
  total INTEGER NOT NULL
);
INSERT INTO member (name) VALUES ('kim'), ('lee');
INSERT INTO orders (member_id, total) VALUES (1, 104000);
INSERT INTO orders (member_id, total) VALUES (99, 15000);
DELETE FROM member WHERE id = 1;
```

```
ERROR:  insert or update on table "orders" violates foreign key constraint "orders_member_id_fkey"
DETAIL:  Key (member_id)=(99) is not present in table "member".
ERROR:  update or delete on table "member" violates foreign key constraint "orders_member_id_fkey" on table "orders"
DETAIL:  Key (id)=(1) is still referenced from table "orders".
```

표를 비우고 번호를 1부터 다시 세려면 `TRUNCATE ... RESTART IDENTITY`를 써요. `member`만 적으면 막히고, `orders`와 같이 적으면 비워져요.

```sql
TRUNCATE member RESTART IDENTITY;
TRUNCATE orders, member RESTART IDENTITY;
INSERT INTO member (name) VALUES ('park');
SELECT * FROM member;
```

```
ERROR:  cannot truncate a table referenced in a foreign key constraint
DETAIL:  Table "orders" references "member".
HINT:  Truncate table "orders" at the same time, or use TRUNCATE ... CASCADE.
```

같이 비운 뒤 넣은 `park`는 1번이에요. 수업에서 쓴 `TRUNCATE enrollments, lockers, courses, instructors, sports, members RESTART IDENTITY;`도 이어진 표를 한 줄에 다 적은 모양이에요.

자식 표 `orders`부터 지워야 `member`도 지워져요.

```sql
DROP TABLE orders;
DROP TABLE member;
```

### 5. ALTER TABLE

```sql
CREATE TABLE member (id INTEGER, name VARCHAR(20), email VARCHAR(50));
INSERT INTO member VALUES (1, 'kim', 'kim@mail.com'), (2, 'lee', 'kim@mail.com');
ALTER TABLE member ADD CONSTRAINT member_email_key UNIQUE (email);
UPDATE member SET email = 'lee@mail.com' WHERE id = 2;
ALTER TABLE member ADD CONSTRAINT member_email_key UNIQUE (email);
ALTER TABLE member ALTER COLUMN name SET NOT NULL;
ALTER TABLE member ADD PRIMARY KEY (id);
\d member
ALTER TABLE member DROP CONSTRAINT member_email_key;
DROP TABLE member;
```

첫 `ADD CONSTRAINT`는 이미 겹친 이메일 때문에 막혀요.

```
ERROR:  could not create unique index "member_email_key"
DETAIL:  Key (email)=(kim@mail.com) is duplicated.
```

### 6. 28 장바구니를 표로

```sql
CREATE TABLE member (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(20) NOT NULL,
  email VARCHAR(50) NOT NULL UNIQUE
);
CREATE TABLE product (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(20) NOT NULL,
  price INTEGER NOT NULL CHECK (price > 0),
  stock INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0)
);
CREATE TABLE cart_item (
  member_id INTEGER REFERENCES member (id) ON DELETE CASCADE,
  product_id INTEGER REFERENCES product (id),
  qty INTEGER NOT NULL CHECK (qty > 0),
  PRIMARY KEY (member_id, product_id)
);
INSERT INTO member (name, email) VALUES ('kim', 'kim@mail.com'), ('lee', 'lee@mail.com');
INSERT INTO product (name, price, stock) VALUES ('earphone', 89000, 3), ('tumbler', 15000, 10), ('battery', 32000, 5), ('mousepad', 9000, 0), ('usb hub', 30000, 10);
INSERT INTO cart_item VALUES (1, 1, 1), (1, 2, 2);
INSERT INTO cart_item VALUES (1, 2, 1);
UPDATE cart_item SET qty = qty + 1 WHERE member_id = 1 AND product_id = 2;
SELECT * FROM cart_item;
```

```
 member_id | product_id | qty
-----------+------------+-----
         1 |          1 |   1
         1 |          2 |   3
(2 rows)
```

같은 상품을 `INSERT`로 또 담으면 `cart_item_pkey`에 걸려요. 28의 `self.items.get(product, 0) + qty`처럼 `UPDATE`로 수량을 늘려요. psql 표의 줄이 맞도록 상품 이름은 영어로 적었어요.

## 명령어 요약

| 명령 | 하는 일 |
| --- | --- |
| `열 타입 NOT NULL` | 비우면 막아요 |
| `열 타입 DEFAULT 값` | 안 적으면 값을 넣어요(`now()`는 지금 시각) |
| `열 타입 UNIQUE` | 같은 값이 두 번 못 들어가요 |
| `열 타입 CHECK (조건)` | 조건이 참인 값만 받아요 |
| `CONSTRAINT 이름 규칙` | 규칙에 이름을 붙여요 |
| `id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY` | 번호를 자동으로 채우는 기본 키 |
| `PRIMARY KEY (a, b)`, `UNIQUE (a, b)` | 두 열의 쌍이 겹치지 않게 해요 |
| `열 INTEGER REFERENCES 표 (열)` | 다른 표에 있는 값만 받아요 |
| `ON DELETE CASCADE` / `RESTRICT` / `SET NULL` | 부모 행을 지울 때 자식 행을 어떻게 할지 |
| `ALTER TABLE 표 ADD CONSTRAINT 이름 규칙;` | 만든 표에 규칙을 더해요 |
| `ALTER TABLE 표 DROP CONSTRAINT 이름;` | 규칙을 지워요 |
| `ALTER TABLE 표 ALTER COLUMN 열 SET NOT NULL;` | NOT NULL 붙이기(`DROP NOT NULL`로 빼기) |
| `ALTER TABLE 표 ALTER COLUMN 열 SET DEFAULT 값;` | 기본값 바꾸기 |
| `TRUNCATE 표;` | 표를 통째로 비워요(번호는 이어서) |
| `TRUNCATE 표1, 표2 RESTART IDENTITY;` | 여러 표를 한 번에 비우고 번호를 1부터 |
| `\d 표` | 붙은 규칙 보기 |

## 문제 해결

| 메시지 | 원인 | 해결 |
| --- | --- | --- |
| `null value in column "name" ... violates not-null constraint` | `NOT NULL` 열을 비웠어요 | 그 열에 값을 넣어요 |
| `duplicate key value violates unique constraint "..._key"` | `UNIQUE` 열에 같은 값 | DETAIL의 겹친 값을 바꿔요 |
| `duplicate key value violates unique constraint "..._pkey"` | 기본 키가 겹쳐요. `SERIAL` 열에 번호를 직접 넣은 뒤에도 나요 | 번호 열은 `INSERT`에서 빼요 |
| `violates check constraint "..."` | `CHECK` 조건이 거짓 | 조건에 맞게 값을 고쳐요 |
| `cannot insert a non-DEFAULT value into column "id"` | `ALWAYS AS IDENTITY` 열에 번호를 넣었어요 | 번호 열을 `INSERT`에서 빼요 |
| `insert or update on table ... violates foreign key constraint` | 부모 표에 없는 번호 | 부모 행을 먼저 넣어요 |
| `update or delete on table ... violates foreign key constraint` | 자식이 쓰는 부모 행을 지웠어요 | 자식 행부터 지우거나 `ON DELETE`를 정해요 |
| `relation "member" does not exist` | 부모 표보다 자식 표를 먼저 만들었어요 | 부모 표부터 만들어요 |
| `cannot drop table member because other objects depend on it` | 자식 표가 남아 있어요 | 자식 표부터 지워요 |
| `cannot truncate a table referenced in a foreign key constraint` | 자식 표가 가리키는 부모 표만 비웠어요 | `TRUNCATE 자식, 부모`처럼 같이 적어요 |
| `could not create unique index` | 이미 겹친 값이 있어서 `UNIQUE`를 못 붙여요 | `UPDATE`로 고친 뒤 다시 |
| `column "name" ... contains null values` | 비어 있는 행이 있어서 `NOT NULL`을 못 붙여요 | 빈칸부터 채워요 |
| NULL이 두 번 들어가요 | `UNIQUE`와 `CHECK`는 NULL을 막지 않아요 | `NOT NULL`을 같이 붙여요 |

  *.html                     한 장에 한 파일 (1920×1080, 발표자 노트는 <aside>)
