10. 실제 상황 예제

팀원이 넣은 패키지는 pull 뒤 uv sync로 받아요

kim 컴퓨터

$ git status --short

 M pyproject.toml

 M uv.lock

$ git add pyproject.toml uv.lock

$ git commit -m "feat: requests 패키지 넣기"

[main faabfb6] feat: requests 패키지 넣기

$ git push origin main

   0a438ca..faabfb6 main -> main

올리는 건 목록 파일 두 개예요. .venv는 올라가지 않아요.

lee 컴퓨터

$ git pull origin main

Fast-forward

 pyproject.toml | 1 +

 uv.lock | 133 +++++++++…

$ uv sync

Installed 4 packages in 3ms

 + requests==2.34.2 …

$ uv tree --depth 1

hello-uv v0.1.0

├── fastapi v0.162.2

├── requests v2.34.2

└── ipykernel v7.4.0 (group: dev)

pull은 목록 파일만 바꿔요. 내 .venv에 실제로 설치하는 건 uv sync예요.

팀원이 패키지를 넣고 push했으면 git pull origin main 뒤에 uv sync를 쳐요. kim은 앞 장에서 넣은 requests를 커밋해서 올렸어요. git add는 바뀐 두 파일 pyproject.toml과 uv.lock을 적어요. lee는 pull로 두 파일을 받고, uv sync로 requests와 따라온 패키지를 .venv에 설치했어요. uv tree --depth 1로 보면 lee의 프로젝트에도 requests가 들어 있어요. pull에서 fatal: Need to specify how to reconcile divergent branches.가 나오면 31쪽처럼 pull.rebase false를 설정해요. 출력은 tools/demo.sh로 실제로 실행한 결과이고, pull 출력 앞부분과 설치 목록 3줄, uv tree의 Resolved 줄은 뺐어요.
