2. 예전 방식과 비교

가상환경은 프로젝트마다 따로 쓰는 패키지 상자예요

컴퓨터에 설치한 파이썬

여기에 바로 넣으면 모든 프로젝트가 같이 써요

project-a/

main.py

.venv/

fastapi 0.162.0

project-b/

main.py

.venv/

fastapi 0.110.0

프로젝트끼리 패키지 버전이 달라도 부딪히지 않아요. uv도 이 .venv를 그대로 써요.

가상환경이 없으면 패키지가 컴퓨터 파이썬 한 곳에 쌓여요. 그러면 A 프로젝트는 fastapi 0.162, B 프로젝트는 0.110이 필요할 때 둘 중 하나가 깨져요. 그래서 프로젝트 폴더마다 .venv라는 상자를 두고 그 안에 패키지를 넣어요. .venv는 점으로 시작해서 ls -a로만 보여요(01). 이 개념은 uv에서도 똑같아요. 다른 건 누가 상자를 만들고 켜느냐예요.

파이썬, 가상환경, 목록 적기는 uv가 대신해요. 직접 치는 건 uv로 시작하는 명령뿐이에요.

같은 웹 서버 프로젝트를 예전 방식과 uv로 만들 때 치는 명령이에요. 예전에는 왼쪽 여섯 단계를 순서대로 직접 챙겼어요. 하나라도 빼먹으면 ModuleNotFoundError가 났어요. uv는 init, add, run 세 명령만 쳐요. 나머지 세 칸은 uv가 알아서 해요. 예전 방식은 따라 치지 않고 눈으로만 봐요. Windows Git Bash에서는 예전 3번이 source .venv/Scripts/activate예요. 인터넷 자료에 pip install이 아직 많이 나와요. 우리 프로젝트에서는 uv add로 바꿔 쳐요.

1번은 ipykernel 없이 셀을 실행하면 VS Code가 띄우는 알림이에요. Install 버튼은 pip로 설치해서 pyproject.toml과 uv.lock에 적히지 않아요. 알림을 닫고 터미널에서 uv add --dev ipykernel을 쳐요. 그다음 커널을 다시 골라요. 2번은 VS Code로 hello-uv의 부모 폴더를 열었거나, clone 뒤 uv sync를 안 해서 .venv가 없을 때 나요. 3번은 컴퓨터에 원래 있던 파이썬을 커널로 고른 경우예요. 2번 셀 출력으로 어느 파이썬인지 확인해요.

정리

예전 명령은 이렇게 바뀌었어요

python.org에서 설치

없으면 uv가 받아요

python3 -m venv .venv

uv run, uv sync가 만들어요

source .venv/bin/activate

uv run이 대신해요. 켜도 돼요

pip install fastapi

uv add fastapi

pip uninstall fastapi

uv remove fastapi

pip install -r requirements.txt

uv sync

python main.py

uv run main.py

인터넷 자료나 옛 강의에 왼쪽 명령이 나오면 오른쪽으로 바꿔 쳐요. 특히 pip install 패키지는 uv add 패키지로 바꿔요. pip로 넣으면 pyproject.toml과 uv.lock에 적히지 않아서 다른 컴퓨터에서 uv sync로 받을 수 없어요.

이미 만든 프로젝트 안에서 uv init을 쳤어요

uv init은 처음 한 번만

1번은 설치 직후에 가장 많이 나요. Mac 기본 터미널은 zsh라서 zsh: command not found: uv로 보여요. 2번은 홈 폴더처럼 pyproject.toml이 없는 곳에서 uv add를 친 경우예요. pwd로 위치를 보고 프로젝트 폴더로 cd 해요. 3번은 가상환경을 켜지 않고 python3 main.py로 실행했거나, uv add를 안 한 경우예요. 서버는 uv run fastapi dev main.py로 켜요. 4번은 폴더 주소가 들어간 메시지예요. 이미 pyproject.toml이 있어서 다시 만들 필요가 없어요.

한 장 요약

uv init 이름

프로젝트 폴더 만들기

uv run main.py

가상환경에서 실행

uv add 패키지

패키지 넣기

uv remove 패키지

패키지 빼기

uv sync

uv.lock대로 맞추기

uv tree

패키지 관계 보기

GitHub에 올려요 pyproject.toml uv.lock .python-version

올리지 않아요 .venv uv init이 .gitignore에 적어 둬요

노트북 uv add --dev ipykernel 뒤 커널로 .venv 고르기

파이썬 프로젝트에서 치는 명령은 거의 이 여섯 개예요. 새 프로젝트는 uv init, 실행은 uv run, 패키지는 uv add와 uv remove, 받은 프로젝트는 uv sync예요. pip install이 보이면 uv add로 바꿔 쳐요.
