pull 하기 전에 설정 한 줄

git config --global pull.rebase false

git pull

pull.rebase false는 합칠 때 merge로 하라는 뜻이에요. 셋 다 처음 한 번만 쳐요.

fatal: Need to specify how to reconcile divergent branches.

설정을 안 하면 오늘 실습 중간에 pull이 이 메시지로 멈춰요. 13쪽에서 다시 봐요.

03에서 본 설정이에요. 아직 안 했다면 셋 다 지금 쳐요. 출력은 없어요. --global이라 내 컴퓨터의 모든 저장소에 적용돼서 한 번만 하면 돼요. 이 설정이 없으면 내 main과 GitHub main이 갈라졌을 때 pull이 어떻게 합칠지 물으면서 fatal로 멈춰요. 오늘 실습은 그 상황이 반드시 생겨요. git config --global pull.rebase로 값을 확인할 수 있어요. false가 나오면 된 거예요. rebase는 이 과정에서 다루지 않아요.

4부 · 팀 규칙

엉키지 않게, 엉켜도 쉽게

1

작업 전에 pull

git pull origin main 부터. park처럼 거절 없이 시작해요

2

작게 자주 커밋하고 push

커밋이 작을수록 충돌도 작아요. 한 커밋에 한 가지만

3

파일과 줄을 나눠 맡기

같은 줄은 동시에 고치지 않기로 미리 말해요

4

거절되면 pull, --force는 금지

5

충돌은 같이 보고 정하기

혼자 지우지 말고 고친 사람에게 물어봐요

오늘 겪은 일에서 나온 규칙이에요. 1번은 park, 4번은 lee의 첫 push에서 봤어요. 3번은 3부 충돌을 막는 방법이에요. 2번은 충돌이 나더라도 고칠 양을 줄여 줘요. 팀이 처음 모였을 때 누가 어떤 파일을 맡을지 정해 두면 3번이 쉬워요.

4부 · 팀 규칙

한 번 작업할 때 이 순서로 돌아요

1 · 받기

git pull origin main

2 · 작업

파일 고치기

3 · 담기

git add 파일

4 · 저장

git commit -m "..."

5 · 올리기

git push origin main

push가 거절되면 1번으로

pull에서 CONFLICT가 나면

파일 고치기 → git add 파일 → git commit -m "fix: ..." → git push origin main

하루에 이 순환을 여러 번 돌아요. push가 거절되면 놀라지 말고 다시 1번 pull로 돌아가요. pull에서 충돌이 나면 3부에서 한 것처럼 고치고 add, commit, push해요.
