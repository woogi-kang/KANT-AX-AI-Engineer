main 하나를 같이 쓰는 건 연습용이에요

오늘: 모두 main에 바로 push

거절, pull, 충돌을 가장 빨리 겪어 보는 방법이에요. 사람이 늘면 서로 기다리는 일이 많아져요.

다음: 각자 브랜치, Pull Request

feature/이름 브랜치에서 일하고 Pull Request로 main에 합쳐요. 03의 7부 GitHub에서 함께를 이어서 봐요.

git checkout -b feature/kim-intro
git push origin feature/kim-intro

브랜치를 써도 Pull Request를 합친 뒤엔 오늘처럼 git pull origin main으로 맞춰요.

실제 팀은 main에 바로 push하지 않고 브랜치와 Pull Request를 써요. 그 흐름은 03 브랜치 덱의 7부에 있어요. 오늘 익힌 pull과 충돌 풀기는 거기서도 그대로 써요. PR 화면의 This branch has conflicts도 내 브랜치에서 git pull origin main으로 푸는 같은 방법이에요.
