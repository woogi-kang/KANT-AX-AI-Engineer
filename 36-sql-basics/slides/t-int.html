2. 자료형 고르기

정수는 담을 수 있는 크기에 따라 세 가지예요

SMALLINT

2바이트

-32,768 ~ 32,767

재고, 나이

INTEGER

4바이트

약 -21억 ~ 21억

가격, 포인트

BIGINT

8바이트

약 -922경 ~ 922경

아주 큰 주문 번호

kant_shop=# CREATE TABLE type_int (s SMALLINT, i INTEGER, b BIGINT);

CREATE TABLE

kant_shop=# INSERT INTO type_int VALUES (32767, 2147483647, 9223372036854775807);

INSERT 0 1

kant_shop=# INSERT INTO type_int VALUES (32768, 1, 1);

ERROR:  smallint out of range

kant_shop=# INSERT INTO type_int VALUES (1, 2147483648, 1);

ERROR:  integer out of range

32,767보다 1 커요

21억을 넘었어요

모르겠으면 INTEGER를 써요. 가격도 재고도 21억을 넘을 일은 드물어요.

정수는 담을 수 있는 크기에 따라 세 가지예요. SMALLINT는 2바이트라서 3만 2767까지만 담아요. INTEGER는 4바이트로 약 21억까지, BIGINT는 8바이트로 약 922경까지 담아요. 막대 길이는 실제 비율이 아니고 크기 순서만 보여 줘요. 연습 표에 세 열을 만들고 각자 가장 큰 값을 넣으면 잘 들어가요. SMALLINT에 1을 더한 3만 2768을 넣으면 smallint out of range, INTEGER 칸에 21억을 넘는 값을 넣으면 integer out of range 오류가 나요. 큰 칸일수록 저장 공간을 더 써요. 보통은 INTEGER를 쓰고, 재고처럼 작은 값은 SMALLINT, 아주 큰 번호는 BIGINT를 써요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
