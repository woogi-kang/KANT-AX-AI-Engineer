같은 이메일 회원이 두 명이어도 막지 않아요

UNIQUE

가격에 -5000을 넣어도 들어가요

CHECK (price >= 0)

가입일을 매번 손으로 적어요

DEFAULT now()

id 번호를 매번 손으로 적어요

SERIAL · IDENTITY

주문 표가 없는 회원을 가리켜도 몰라요

FOREIGN KEY

그다음에는 표 두 개를 잇는 JOIN, 줄을 묶어 세는 GROUP BY와 COUNT, SUM을 배워요. 오늘은 이름만 알아 둬요.

37에서는 잘못된 값이 아예 못 들어오게 표를 설계해요. 오늘 왼쪽 같은 빈틈을 봤어요. 가격이 NULL인 상품이 들어갔고, 같은 이메일로 회원이 두 번 가입해도 막을 방법이 없었어요. 가격에 음수를 넣어도 들어가고, 가입일과 id를 매번 손으로 적었어요. 37에서는 표를 만들 때 NOT NULL, UNIQUE, CHECK 같은 제약 조건을 붙여서 이런 값이 들어오면 오류가 나게 해요. 번호를 자동으로 매기는 SERIAL과 IDENTITY, 표끼리 잇는 FOREIGN KEY도 배워요. 그다음에는 두 표를 합쳐 보는 JOIN과, 줄을 묶어 세는 GROUP BY, COUNT, SUM을 배워요.
