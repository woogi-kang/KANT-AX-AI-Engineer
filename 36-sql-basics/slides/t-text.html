CHAR(n)는 남는 칸을 공백으로 채우고, VARCHAR(n)는 길이만 막아요

다섯 칸 꽉 참

PostgreSQL에서는 셋의 빠르기가 같아요. 길이를 막을 이유가 없으면 TEXT, 막아야 하면 VARCHAR(n)를 써요.

CHAR는 남는 칸을 공백으로 채우고, VARCHAR는 길이만 막아요. 연습 표 type_text에 세 종류 열을 하나씩 만들었어요. code는 CHAR 5, name은 VARCHAR 5, memo는 TEXT예요. 'A1'을 넣고 꺼내 보면 code 칸이 다섯 칸으로 넓어요. CHAR 5는 늘 다섯 글자라서 남는 세 칸을 공백으로 채워 둬요. VARCHAR 5는 다섯 글자까지만 받아요. keyboard처럼 여덟 글자를 넣으면 value too long 오류가 나요. CHAR 5에 일곱 글자를 넣어도 같은 오류예요. TEXT는 길이 제한이 없어요. PostgreSQL 문서에도 세 가지의 빠르기 차이가 없다고 적혀 있어요. 그래서 보통 TEXT를 쓰고, 이름처럼 너무 길면 안 되는 칸은 VARCHAR에 길이를 적어요. CHAR는 우편번호처럼 길이가 늘 같은 값에만 써요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
