2. 자료형 고르기

DOUBLE PRECISION은 0.1 + 0.2를 정확히 0.3으로 계산하지 못해요

kant_shop=# CREATE TABLE type_num (fa DOUBLE PRECISION, fb DOUBLE PRECISION, na NUMERIC(10, 2), nb NUMERIC(10, 2));

CREATE TABLE

kant_shop=# INSERT INTO type_num VALUES (0.1, 0.2, 0.1, 0.2);

INSERT 0 1

kant_shop=# SELECT fa + fb, na + nb FROM type_num;

     ?column?       | ?column?

DOUBLE PRECISION은 0.1 더하기 0.2를 정확히 0.3으로 계산하지 못해요. 연습 표 type_num에 같은 0.1과 0.2를 두 번 넣었어요. 앞의 두 열은 DOUBLE PRECISION, 뒤의 두 열은 NUMERIC이에요. 더해 보면 DOUBLE PRECISION은 0.30000000000000004가 나와요. 컴퓨터가 소수를 2진수로 바꿔 담으면서 아주 작은 차이가 생기기 때문이에요. NUMERIC은 적은 숫자 그대로 계산해서 0.30이 나와요. 아래 표는 원주율을 세 칸에 넣어 본 결과예요. REAL은 약 6자리, DOUBLE PRECISION은 약 15자리까지만 맞고, NUMERIC 5, 2는 소수 둘째 자리까지 정확하게 담아요. 돈처럼 1원도 틀리면 안 되는 값은 NUMERIC을 써요. 계산한 열에는 이름이 없어서 psql이 ?column?으로 보여 줘요. 터미널 출력은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
