5. YAML과 compose

compose config는 파일을 읽은 그대로 펼쳐 보여 줘요

~/kant-shop $ docker compose config

name: kant-shop

services:

 db:

   container_name: my-pg

   environment:

     POSTGRES_PASSWORD: admin1234

   image: postgres:18

   networks:

     default: null

   volumes:

     - type: volume

       source: pgdata

       target: /var/lib/postgresql

       volume: {}

   ports:

     - mode: ingress

       target: 5432

       published: "5432"

       protocol: tcp

networks:

 default:

   name: kant-shop_default

volumes:

 pgdata:

   name: kant-shop_pgdata

폴더 이름이 프로젝트 이름

내가 적은 칸

볼륨 이름 앞에 kant-shop_

up 하기 전에 쳐 봐요

파일에 오류가 있으면 여기서 오류가 나요. 오류가 없으면 Docker가 알아들은 내용을 빠짐없이 펼쳐 보여 줘요. 순서가 바뀌고 안 적은 칸이 채워져 있어도 괜찮아요.

docker compose config는 compose.yaml을 읽은 그대로 펼쳐 보여 줘요. 내가 적은 칸은 그대로 있고, 안 적은 칸은 Docker가 기본값으로 채워 넣어요. 순서도 이름순으로 바뀌어요. 눈여겨볼 곳이 두 군데 있어요. 맨 위 name: kant-shop은 폴더 이름이 프로젝트 이름이 된다는 뜻이에요. 맨 아래 볼륨 이름은 kant-shop_pgdata예요. compose로 만든 볼륨에는 앞에 프로젝트 이름이 붙어요. 4파트에서 docker volume create로 만든 pgdata와는 다른 볼륨이에요. compose.yaml을 고친 뒤 up 하기 전에 config를 쳐 보면, YAML 오류는 여기서 먼저 나와요. 터미널 출력은 tools/demo.py로 실제 Docker와 postgres:18 이미지를 실행한 결과예요.
