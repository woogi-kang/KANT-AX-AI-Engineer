5. YAML과 compose

logs, stop, start, restart 앞에 compose만 붙여요

~/kant-shop $ docker compose logs --tail 3

my-pg  | 2026-11-13 04:45:01.081 UTC [1] LOG:  listening on Unix socket "/var/run/postgresql/.s.PGSQL.5432"

my-pg  | 2026-11-13 04:45:01.084 UTC [73] LOG:  database system was shut down at 2026-11-13 04:45:00 UTC

my-pg  | 2026-11-13 04:45:01.086 UTC [1] LOG:  database system is ready to accept connections

~/kant-shop $ docker compose logs -f --tail 2

my-pg  | 2026-11-13 04:45:01.084 UTC [73] LOG:  database system was shut down at 2026-11-13 04:45:00 UTC

my-pg  | 2026-11-13 04:45:01.086 UTC [1] LOG:  database system is ready to accept connections

^C

~/kant-shop $ docker compose stop

[+] stop 1/1

✔ Container my-pg Stopped                                                  0.2s

~/kant-shop $ docker compose ps -a

NAME      IMAGE         COMMAND                  SERVICE   CREATED         STATUS                              PORTS

my-pg     postgres:18   "docker-entrypoint.s…"   db        5 seconds ago   Exited (0) Less than a second ago

~/kant-shop $ docker compose start

[+] start 1/1

✔ Container my-pg Started                                                  0.1s

~/kant-shop $ docker compose restart

Container my-pg Started

줄 앞에 컨테이너 이름이 붙어요

Ctrl+C로 멈춰요

ps -a로 꺼진 것까지

껐다가 바로 켜요

logs, stop, start, restart는 2파트에서 본 명령 앞에 compose만 붙이면 돼요. 이름을 안 적어도 이 폴더의 compose.yaml에 있는 서비스 전부에 적용돼요. compose logs는 줄 앞에 컨테이너 이름이 붙어요. 서비스가 여러 개일 때 누가 남긴 기록인지 알 수 있어요. --tail과 -f도 똑같이 써요. compose stop으로 끄면 compose ps에는 안 보이고 ps -a에 Exited로 남아요. compose start로 다시 켜고, restart는 껐다가 바로 켜요. 컨테이너를 지우지 않으니 데이터는 그대로예요. 화면에서는 기록 줄 앞의 날짜와 번호를 줄였어요. 터미널 출력은 tools/demo.py로 실제 Docker와 postgres:18 이미지를 실행한 결과예요.
