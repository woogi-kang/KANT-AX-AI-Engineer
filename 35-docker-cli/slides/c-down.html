5. YAML과 compose

down은 컨테이너를 지우고 볼륨은 남겨요. down -v는 볼륨까지 지워요

~/kant-shop $ docker compose down

[+] down 2/2

✔ Container my-pg           Removed                                        0.2s

✔ Network kant-shop_default Removed                                        0.1s

~/kant-shop $ docker volume ls

DRIVER    VOLUME NAME

local     kant-shop_pgdata

~/kant-shop $ docker compose up -d

[+] up 2/2

✔ Network kant-shop_default Created                                        0.0s

✔ Container my-pg           Started                                        0.2s

~/kant-shop $ docker compose exec db psql -U postgres -d kant_shop -c "SELECT * FROM product"

id |     name      | price  | stock

----+---------------+--------+-------

 1 | 무선 이어폰   |  35000 |   100

 2 | 게이밍 마우스 |  28000 |    85

… (5 rows)

~/kant-shop $ docker compose down -v

[+] down 3/3

✔ Container my-pg           Removed                                        0.2s

✔ Network kant-shop_default Removed                                        0.2s

✔ Volume kant-shop_pgdata   Removed                                        0.1s

~/kant-shop $ docker volume ls

DRIVER    VOLUME NAME

down 뒤에도 볼륨이 남아요

다시 up 하면 상품이 그대로

-v는 볼륨까지 지워요

docker compose down은 컨테이너와 네트워크를 지우고 볼륨은 남겨요. 33, 34에서 본 그대로예요. down 뒤에 docker volume ls를 치면 kant-shop_pgdata가 남아 있어요. 그래서 다시 up -d로 켜면 kant_shop의 상품이 그대로 나와요. 수업이 끝나고 내일 다시 켤 때 이렇게 쓰면 돼요. down -v는 볼륨까지 지워요. Removed 줄에 Volume이 보이고, volume ls가 비어요. 데이터를 처음부터 다시 만들고 싶을 때만 -v를 붙여요. 터미널 출력은 tools/demo.py로 실제 Docker와 postgres:18 이미지를 실행한 결과예요.
