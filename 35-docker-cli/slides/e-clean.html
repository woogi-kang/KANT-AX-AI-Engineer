6. 오류와 실제 상황

예제 3. 다 쓴 것은 컨테이너, 볼륨, 이미지 순서로 지워요

~/kant-shop $ docker compose down -v

[+] down 3/3

✔ Container my-pg           Removed                                        0.2s

✔ Volume kant-shop_pgdata   Removed                                        0.1s

✔ Network kant-shop_default Removed                                        0.2s

~/kant-shop $ docker ps -a

CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES

~/kant-shop $ docker volume ls

DRIVER    VOLUME NAME

~/kant-shop $ docker rmi postgres:18

Untagged: postgres:18

Deleted: sha256:b9f6b8ff03b62f3cfd9d9ba3fe56226a9991c79d3fb46fd46536263bf02be553

~/kant-shop $ docker images

IMAGE   ID             DISK USAGE   CONTENT SIZE   EXTRA

compose로 켰다면

docker compose down -v docker rmi postgres:18

docker run으로 켰다면

docker stop my-pg docker rm my-pg docker volume rm pgdata docker rmi postgres:18

빈 ps -a, 빈 volume ls, 빈 images가 다 지운 모습이에요.

이미지는 다음 수업에 또 쓸 거라면 남겨 둬요. 지우면 다음에 pull부터 다시 해요.

예제 3은 다 쓴 것을 정리하는 순서예요. 컨테이너, 볼륨, 이미지 순서로 지워요. compose로 켰다면 docker compose down -v 한 줄로 컨테이너와 볼륨, 네트워크까지 지워져요. 그다음 docker rmi로 이미지를 지워요. ps -a, volume ls, images가 모두 비면 다 지운 거예요. docker run으로 켰다면 stop, rm, volume rm, rmi를 차례로 쳐요. 순서를 바꾸면 2파트와 4파트에서 본 오류가 나요. 볼륨을 지우면 상품 데이터도 사라지니 다시 쓸 거라면 남겨요. 이미지도 다음 수업에 또 쓸 거라면 남겨 두는 게 좋아요. 터미널 출력은 tools/demo.py로 실제 Docker와 postgres:18 이미지를 실행한 결과예요.
