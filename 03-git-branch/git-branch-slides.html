만들고 옮기기

브랜치만 옮기는 명령, git switch

git checkout

git switch

브랜치로 옮겨 가기

git checkout 이름

git switch 이름

만들고 바로 옮겨 가기

git checkout -b 이름

git switch -c 이름

$ git switch feature/login

Switched to branch 'feature/login'

$ git switch -c feature/login-button

Switched to a new branch 'feature/login-button'

하는 일과 출력은 같아요. 이 덱은 checkout으로 보여 주고, switch로 쳐도 돼요.

git switch는 Git 2.23(2019년)에 생긴 명령이에요. checkout은 브랜치를 옮기는 일 말고 파일을 예전 모습으로 되돌리는 일도 해서 헷갈리기 쉬워요. 그래서 브랜치를 옮기는 일만 따로 떼어 switch를 만들었어요. -c는 create(만들기)의 첫 글자예요. 내 Git이 오래돼서 switch가 없다고 나오면 git --version으로 버전을 확인해요. 팀 자료나 인터넷 글에는 두 명령이 섞여 나오니 둘 다 읽을 수 있으면 돼요.

git merge 이름은 그 이름의 커밋을 지금 내가 있는 브랜치로 가져와요. 그래서 순서가 중요해요. 먼저 받을 쪽(main)으로 checkout하고, 그다음 가져올 브랜치 이름을 적어요. 반대로 feature/login에 있는 채로 git merge main을 치면 main의 커밋이 feature/login으로 들어가요. 02에서 git pull origin main을 배울 때 merge는 03에서 본다고 했죠. pull은 GitHub의 main을 받아 온 뒤 지금 브랜치로 merge해요.

GitHub Flow는 main 하나와 짧게 쓰고 지우는 작업 브랜치로만 일하는 방식이에요. 갈래가 길어질수록 main과 멀어져 충돌이 커지니, 하루 이틀 안에 합칠 수 있는 크기로 나눠요. GitHub 저장소 설정에서 main 브랜치 보호(Branch protection)를 켜면 main에 직접 push를 막고 PR로만 합치게 할 수 있어요.

충돌 시나리오 3 · 지움 vs 고침

지울지 남길지 골라요

$ git status

Unmerged paths:

(use "git add/rm <file>..." as appropriate to mark resolution)

    deleted by them: old-login.md

지우기로 하면

git rm old-login.md

git commit -m "..."

남기기로 하면

git add old-login.md

git commit -m "..."

deleted by them은 합치려는 브랜치(them)가 지웠다는 뜻이에요.

git status 앞뒤 안내 줄은 뺐어요. 이번 실습에서는 git rm old-login.md로 지우기를 골랐고 출력은 rm 'old-login.md'였어요. 이어서 git commit -m "chore: 옛 로그인 화면 삭제 반영"을 하면 [main 7e68b90] chore: 옛 로그인 화면 삭제 반영이 나와요. 내가 지운 쪽이면 deleted by us로 보여요.

PR 충돌

내 브랜치에서 pull origin main, 풀고 push

어떤 충돌이든 막히면 git merge --abort로 처음으로 돌아갈 수 있어요.

메시지 첫 단어만 봐도 무엇을 할지 알 수 있어요. 충돌을 푼 뒤에는 git status로 남은 충돌 파일이 없는지 확인하고 커밋해요.

에러 1 · 브랜치 이름

옮기려는데, 만들려는데 안 돼요

없는 브랜치로 옮김

$ git checkout feature/nope
error: pathspec 'feature/nope' did not match any file(s) known to git

이름 오타이거나 아직 안 만든 브랜치예요

git branch

git checkout -b feature/nope

이미 있는 이름으로 만듦

$ git checkout -b feature/login
fatal: a branch named 'feature/login' already exists

같은 이름이 벌써 있어요. -b 없이 옮겨 가요

git checkout feature/login

pathspec 에러는 Git이 브랜치도 파일도 못 찾았다는 뜻이에요. git branch로 목록을 보고 철자를 확인해요. 새로 만들 생각이었다면 -b를 붙여요. already exists는 반대로 이미 있는 이름에 -b를 붙였을 때 나요.

에러 2 · 커밋 안 한 변경

브랜치를 옮기려는데 막혀요

고친 파일이 그대로 있음

error: Your local changes to the following files would be overwritten by checkout:
        login.md
Please commit your changes or stash them before you switch branches.
Aborting

옮겨 가면 고친 내용이 덮어써져서 Git이 멈췄어요. 먼저 커밋하고 옮겨요

git add login.md

git commit -m "feat: ..."

git checkout feature/login

옮겨 갈 브랜치에서 같은 파일 내용이 다를 때만 나요. 고친 내용을 잃지 않게 지켜 주는 에러예요. 작업이 덜 끝났어도 지금 브랜치에 커밋해 두고 옮기면 돼요. 메시지에 나오는 stash(잠깐 치워 두기)는 07에서 배워요.

에러 3 · 브랜치 지우기

브랜치가 안 지워져요

아직 합치지 않은 커밋이 있음

$ git branch -d feature/login
error: the branch 'feature/login' is not fully merged.
If you are sure you want to delete it, run 'git branch -D feature/login'

지우면 그 커밋을 잃을 수 있어서 Git이 멈췄어요

git checkout main

git merge feature/login

git branch -d feature/login

합치고 지우는 게 기본이에요. 정말 버릴 작업일 때만 대문자 -D로 강제로 지워요. GitHub에서 PR을 merge했는데도 이 에러가 나면, 먼저 git checkout main 후 git pull origin main으로 내 main을 최신으로 맞추고 다시 지워 봐요.
