git switch는 Git 2.23(2019년)에 생긴 명령이에요. checkout은 브랜치를 옮기는 일 말고 파일을 예전 모습으로 되돌리는 일도 해서 헷갈리기 쉬워요. 그래서 브랜치를 옮기는 일만 따로 떼어 switch를 만들었어요. -c는 create(만들기)의 첫 글자예요. 내 Git이 오래돼서 switch가 없다고 나오면 git --version으로 버전을 확인해요. 팀 자료나 인터넷 글에는 두 명령이 섞여 나오니 둘 다 읽을 수 있으면 돼요.

reset은 지금 브랜치 이름표를 예전 커밋으로 옮겨서 그 위 커밋을 기록에서 빼요. merge와 상관없이 쓰는 명령이에요. HEAD~1은 지금보다 한 칸 아래 커밋이에요. merge 커밋도 커밋 하나라서 똑같이 한 칸 뒤로 가요. 두 경우 모두 push 전에만 써요. 옵션 --soft, --mixed, --hard는 빠진 커밋의 변경을 어느 칸에 남길지 정해요.

PR을 올린 사이 main이 같은 줄을 바꾸면 PR 화면에 충돌이 떠요. feature/login-title을 push하고 PR을 만들었는데, 그 사이 팀원이 main의 같은 줄을 # 로그인 페이지로 바꿔 합쳤어요. GitHub 화면 문구와 모양은 업데이트에 따라 조금 다를 수 있어요. GitHub에서 Resolve conflicts 버튼으로 웹에서 풀 수도 있지만, 수업에서는 내 컴퓨터에서 푸는 법을 써요.

충돌 시나리오 6 · Pull Request

내 브랜치에서 main을 받아 풀고, 다시 push

$ git checkout feature/login-title

$ git pull origin main

CONFLICT (content): Merge conflict in login.md

# login.md 충돌 표시 지우고 저장

$ git add login.md

$ git commit -m "fix: main과 로그인 제목 충돌 해결"

$ git push origin feature/login-title

c7149cd..8feb440 feature/login-title -> feature/login-title

push하면 PR 화면이 다시 Merge 할 수 있는 상태로 바뀌어요.

main을 내 브랜치로 먼저 가져와서 충돌을 풀어요. 그래서 checkout feature/login-title 다음에 pull origin main이에요. 받는 쪽이 feature/login-title이라는 점이 merge와 같아요. checkout, pull, commit 출력 일부는 뺐어요.

PR 충돌

내 브랜치에서 pull origin main, 풀고 push

어떤 충돌이든 막히면 git merge --abort로 처음으로 돌아갈 수 있어요.

메시지 첫 단어만 봐도 무엇을 할지 알 수 있어요. 충돌을 푼 뒤에는 git status로 남은 충돌 파일이 없는지 확인하고 커밋해요.

에러 1 · 브랜치 이름

옮기려는데, 만들려는데 안 돼요

없는 브랜치로 옮김

$ git checkout feature/nope
error: pathspec 'feature/nope' did not match any file(s) known to git

이름 오타이거나 아직 안 만든 브랜치예요

git branch

git checkout -b feature/nope

이미 있는 이름으로 만듦

$ git checkout -b feature/login
fatal: a branch named 'feature/login' already exists

같은 이름이 벌써 있어요. -b 없이 옮겨 가요

git checkout feature/login

pathspec 에러는 Git이 브랜치도 파일도 못 찾았다는 뜻이에요. git branch로 목록을 보고 철자를 확인해요. 새로 만들 생각이었다면 -b를 붙여요. already exists는 반대로 이미 있는 이름에 -b를 붙였을 때 나요.

에러 2 · 커밋 안 한 변경

브랜치를 옮기려는데 막혀요

고친 파일이 그대로 있음

error: Your local changes to the following files would be overwritten by checkout:
        login.md
Please commit your changes or stash them before you switch branches.
Aborting

옮겨 가면 고친 내용이 덮어써져서 Git이 멈췄어요. 먼저 커밋하고 옮겨요

git add login.md

git commit -m "feat: ..."

git checkout feature/login

옮겨 갈 브랜치에서 같은 파일 내용이 다를 때만 나요. 고친 내용을 잃지 않게 지켜 주는 에러예요. 작업이 덜 끝났어도 지금 브랜치에 커밋해 두고 옮기면 돼요. 메시지에 나오는 stash(잠깐 치워 두기)는 07에서 배워요.

에러 3 · 브랜치 지우기

브랜치가 안 지워져요

아직 합치지 않은 커밋이 있음

$ git branch -d feature/login
error: the branch 'feature/login' is not fully merged.
If you are sure you want to delete it, run 'git branch -D feature/login'

지우면 그 커밋을 잃을 수 있어서 Git이 멈췄어요

git checkout main

git merge feature/login

git branch -d feature/login

-d는 합치지 않은 커밋이 있으면 지우지 않고 멈춰요. 먼저 main에 합친 뒤 지워요. 합치지 않고 버리는 방법은 08에서 다뤄요. GitHub에서 PR을 merge했는데도 이 에러가 나면, 먼저 git checkout main 후 git pull origin main으로 내 main을 최신으로 맞추고 다시 지워 봐요.
