02에서 본 git pull origin main도 받아 온 커밋을 이 방식으로 merge해요.

git merge 이름은 그 이름의 커밋을 지금 내가 있는 브랜치로 가져와요. 그래서 순서가 중요해요. 먼저 받을 쪽(main)으로 checkout하고, 그다음 가져올 브랜치 이름을 적어요. 반대로 feat/greeting에 있는 채로 git merge main을 치면 main의 커밋이 feat/greeting으로 들어가요. 02에서 git pull origin main을 배울 때 merge는 03에서 본다고 했죠. pull은 GitHub의 main을 받아 온 뒤 지금 브랜치로 merge해요.

양쪽에 새 커밋이 있으니 Git이 둘을 합친 새 커밋(merge 커밋)을 만들어요. 이 커밋은 부모가 둘이에요. 편집기에 Merge branch 'docs/usage'라는 메시지가 미리 적혀 있어요. 그대로 저장하고 닫으면 돼요. vim이 열리면 Esc를 누른 뒤 :wq 와 Enter를 쳐요. 합친 뒤 docs/usage는 지웠어요. 그래서 그래프에서 docs/usage 이름표가 사라졌어요. 커밋 d92e18b는 main 기록 안에 그대로 남아요.

Git Flow(develop, release 브랜치를 따로 두는 방식)는 배포 일정이 복잡한 회사에서 써요. 처음엔 GitHub Flow면 충분해요.

GitHub Flow는 main 하나와 짧게 쓰고 지우는 작업 브랜치로만 일하는 방식이에요. 갈래가 길어질수록 main과 멀어져 충돌이 커지니, 하루 이틀 안에 합칠 수 있는 크기로 나눠요. GitHub 저장소 설정에서 main 브랜치 보호(Branch protection)를 켜면 main에 직접 push를 막고 PR로만 합치게 할 수 있어요.

에러 1 · 브랜치 이름

옮기려는데, 만들려는데 안 돼요

없는 브랜치로 옮김

$ git checkout feat/nope
error: pathspec 'feat/nope' did not match any file(s) known to git

이름 오타이거나 아직 안 만든 브랜치예요

git branch

git checkout -b feat/nope

이미 있는 이름으로 만듦

$ git checkout -b feat/a
fatal: a branch named 'feat/a' already exists

같은 이름이 벌써 있어요. -b 없이 옮겨 가요

git checkout feat/a

pathspec 에러는 Git이 브랜치도 파일도 못 찾았다는 뜻이에요. git branch로 목록을 보고 철자를 확인해요. 새로 만들 생각이었다면 -b를 붙여요. already exists는 반대로 이미 있는 이름에 -b를 붙였을 때 나요.

에러 2 · 커밋 안 한 변경

브랜치를 옮기려는데 막혀요

고친 파일이 그대로 있음

error: Your local changes to the following files would be overwritten by checkout:
        hello.md
Please commit your changes or stash them before you switch branches.
Aborting

옮겨 가면 고친 내용이 덮어써져서 Git이 멈췄어요. 먼저 커밋하고 옮겨요

git add hello.md

git commit -m "feat: ..."

git checkout feat/b

옮겨 갈 브랜치에서 같은 파일 내용이 다를 때만 나요. 고친 내용을 잃지 않게 지켜 주는 에러예요. 작업이 덜 끝났어도 지금 브랜치에 커밋해 두고 옮기면 돼요. 메시지에 나오는 stash(잠깐 치워 두기)는 이 과정에서 다루지 않아요.

에러 3 · 브랜치 지우기

브랜치가 안 지워져요

아직 합치지 않은 커밋이 있음

$ git branch -d feat/a
error: the branch 'feat/a' is not fully merged.
If you are sure you want to delete it, run 'git branch -D feat/a'

지우면 그 커밋을 잃을 수 있어서 Git이 멈췄어요

git checkout main

git merge feat/a

git branch -d feat/a

합치고 지우는 게 기본이에요. 정말 버릴 작업일 때만 대문자 -D로 강제로 지워요. GitHub에서 PR을 merge했는데도 이 에러가 나면, 먼저 git checkout main 후 git pull origin main으로 내 main을 최신으로 맞추고 다시 지워 봐요.
