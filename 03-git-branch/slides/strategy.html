Git Flow(develop, release 브랜치를 따로 두는 방식)는 배포 일정이 복잡한 회사에서 써요. 처음엔 GitHub Flow면 충분해요.

GitHub Flow는 main 하나와 짧게 쓰고 지우는 작업 브랜치로만 일하는 방식이에요. 갈래가 길어질수록 main과 멀어져 충돌이 커지니, 하루 이틀 안에 합칠 수 있는 크기로 나눠요. GitHub 저장소 설정에서 main 브랜치 보호(Branch protection)를 켜면 main에 직접 push를 막고 PR로만 합치게 할 수 있어요.
