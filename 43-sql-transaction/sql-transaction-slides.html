수업 파일 주석에 DDL, DML이라는 말이 나왔어요. SQL 문장을 하는 일로 나눈 이름이에요. DDL은 Data Definition Language, 표의 모양을 정하는 문장이에요. CREATE TABLE, DROP TABLE, ALTER TABLE, TRUNCATE가 여기에 들어가요. DML은 Data Manipulation Language, 표 안의 줄을 넣고 고치고 지우고 읽는 문장이에요. INSERT, UPDATE, DELETE, SELECT예요. TCL은 Transaction Control Language예요. 오늘 배우는 BEGIN, COMMIT, ROLLBACK이고, DML 여러 개를 묶어서 확정하거나 취소해요. SELECT는 따로 DQL이라고 부르는 책도 있어요. 이름보다 하는 일을 기억하면 돼요.

트랜잭션 명령을 순서에 맞지 않게 치면 WARNING이 나와요. BEGIN 상태에서 BEGIN을 한 번 더 치면 이미 트랜잭션이 진행 중이라고 알려 줘요. 새 저장 지점이 생기지는 않아요. 그 뒤 첫 ROLLBACK은 정상으로 끝나고, 두 번째 ROLLBACK은 끝낼 트랜잭션이 없다고 나와요. WARNING은 ERROR와 달리 문장을 막지 않는 안내예요. 하지만 내가 생각한 상태와 실제 상태가 다르다는 신호라서, 프롬프트에 별표가 있는지 다시 봐요. psql 화면은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.

오늘 본 메시지와 상황을 모았어요. 위의 두 줄은 WARNING이에요. BEGIN 없이 ROLLBACK을 치면 이미 저장된 뒤라서 되돌릴 수 없어요. 다음부터 BEGIN을 먼저 쳐요. BEGIN을 두 번 치면 그냥 이어서 쓰면 돼요. 셋째와 넷째는 트랜잭션 안에서 오류가 난 경우예요. 프롬프트가 느낌표로 바뀌고, 무엇을 쳐도 무시돼요. COMMIT을 쳐도 ROLLBACK이 돼요. ROLLBACK하고 고쳐서 다시 해요. 다섯째, 다른 창의 UPDATE가 대답이 없으면 BEGIN한 창이 같은 줄을 고치는 중이에요. 여섯째, COMMIT 없이 나가면 바꾼 값은 사라져요.

두 문장이 함께 성공해야 해요 (강좌 옮기기, 탈퇴)

실패, ROLLBACK만 받아요

트랜잭션을 언제 쓰는지 정리해요. 여러 줄을 고치거나 지울 때는 BEGIN을 치고, 줄 수를 확인한 뒤 COMMIT해요. 강좌 옮기기나 회원 탈퇴처럼 두 문장이 함께 성공해야 하면 BEGIN과 COMMIT 사이에 묶어요. 결과를 보기만 하고 싶을 때는 BEGIN 뒤에 UPDATE와 RETURNING을 치고 ROLLBACK해요. 오류가 나서 프롬프트가 느낌표로 바뀌면 ROLLBACK하고 고쳐서 처음부터 다시 해요. 지금 상태는 프롬프트에서 읽어요. 아무 표시가 없으면 자동 저장 중, 별표면 확정 전, 느낌표면 실패한 트랜잭션이에요. 44에서는 파이썬에서 PostgreSQL을 쓰면서 같은 COMMIT이 어디서 일어나는지 봐요.
