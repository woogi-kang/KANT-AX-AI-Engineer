3. 모두 되거나 모두 안 되거나

PostgreSQL은 DROP TABLE과 TRUNCATE도 되돌려요

kant_shop=# BEGIN;

BEGIN

kant_shop=*# DROP TABLE enrollments;

DROP TABLE

kant_shop=*# SELECT COUNT(*) FROM enrollments;

ERROR:  relation "enrollments" does not exist

LINE 1: SELECT COUNT(*) FROM enrollments;

                            ^

kant_shop=!# ROLLBACK;

ROLLBACK

kant_shop=# SELECT COUNT(*) FROM enrollments;

count

-------

  187

(1 row)

kant_shop=# BEGIN;

BEGIN

kant_shop=*# TRUNCATE enrollments;

TRUNCATE TABLE

kant_shop=*# ROLLBACK;

ROLLBACK

kant_shop=# SELECT COUNT(*) FROM enrollments;

count

-------

  187

(1 row)

표가 돌아왔어요

187줄 그대로

모든 데이터베이스가 그렇지는 않아요. MySQL은 DROP TABLE을 치는 순간 저장돼요.

DDL도 트랜잭션 안에서 되돌릴 수 있을까요. BEGIN을 치고 신청 표를 DROP TABLE로 통째로 지웠어요. SELECT하면 그런 표가 없다는 오류가 나고, 프롬프트에 느낌표가 붙어요. ROLLBACK을 치고 다시 세어 보면 187줄이 그대로 있어요. 오른쪽은 37에서 배운 TRUNCATE예요. 표를 비웠다가 ROLLBACK하니 187줄이 돌아왔어요. PostgreSQL은 DROP TABLE과 TRUNCATE도 트랜잭션에 넣어 줘요. 모든 데이터베이스가 그렇지는 않아요. MySQL은 DROP TABLE을 치는 순간 저장돼요. 연습용 표에서 해 보고, 실제 표에서는 DROP을 치지 않아요. psql 화면은 tools/demo.py로 실제 Docker와 PostgreSQL 18을 실행한 결과예요.
