11 챕터는 GitHub 공식 터미널 도구 gh(GitHub CLI)를 다뤄요. 지금까지 레포 만들기, PR 만들기는 GitHub 웹사이트에서 버튼으로 했어요. 오늘은 같은 일을 터미널에서 해요. 로그인부터 시작해서 레포를 받고, 만들고, 지워요. 지울 때 권한이 모자라서 막히는 장면도 일부러 넣었어요. 마지막에는 이슈와 PR을 다루는 명령을 봐요.

오늘 쓰는 도구 셋이 어디에 있는지 그림으로 봐요. 왼쪽 터미널에서 git과 gh를 같이 써요. git은 push와 pull로 커밋 기록을 GitHub과 주고받아요. GitHub의 레포 만들기, PR, 이슈 같은 버튼은 지금까지 브라우저에서 마우스로 눌렀어요. gh는 그 버튼을 터미널 명령으로 눌러요. 그래서 커밋과 push는 계속 git으로 하고, 버튼 일은 gh로 해요. gh가 git을 대신하지 않아요.

gh 다음에 대상, 그다음에 할 일을 적어요.

오늘 쓸 명령을 웹 버튼과 나란히 놓았어요. 왼쪽은 GitHub 웹사이트에서 누르던 버튼, 오른쪽은 같은 일을 하는 gh 명령이에요. 1파트에서 로그인, 2파트에서 clone, 3파트에서 레포 만들기, 4파트에서 지우기, 5파트에서 이슈와 PR을 봐요. gh 명령은 모두 gh 다음에 대상(repo, issue, pr)과 할 일(create, list, delete)을 적는 모양이에요. 파란 글자가 대상, 주황 글자가 할 일이에요.

git push origin main

git이 gh에게 출입증을 받아요

GitHub에 바로 올라가요

02의 첫 push에서 뜨던 로그인 창이 이제 안 떠요.

질문 3에서 Yes를 고르면 gh가 git 설정 파일(~/.gitconfig)에 두 줄을 넣어요. credential은 로그인 정보라는 뜻이에요. github.com에 push 할 때 로그인 정보는 gh auth git-credential에게 물어보라는 설정이에요. 그래서 git push origin main을 치면 git이 gh에게 출입증을 받아서 바로 올려요. 위쪽 [pull] rebase = false는 06에서 넣은 pull 설정이에요. helper = 처럼 빈 줄도 gh가 일부러 넣은 거라 지우지 않아요. 파일 내용은 tools/demo.sh에서 실제로 실행한 결과고, 위아래는 …로 줄였어요. Windows는 /usr/local/bin 자리의 설치 경로가 달라요.

03에서 브랜치를 만들어 push한 뒤 웹에서 Compare & pull request 버튼으로 PR을 열었어요. 위쪽은 03과 같은 순서예요. 브랜치를 만들고, 고치고, 커밋하고, git push origin feature/kim-hobby로 올려요. 아래 gh pr create가 웹 버튼을 대신해요. --title은 PR 제목, --body는 내용이에요. 꼭 push를 먼저 해요. push 전에 gh pr create를 치면 gh가 브랜치를 어디에 push할지 되물어요. push 출력의 가운데는 …로 줄였어요.

5. 자주 쓰는 gh 명령

gh pr list, gh pr view로 PR을 터미널에서 봐요

~/kant/team-intro $ gh pr list

~/kant/team-intro $ gh pr view 2

feat: kim 취미 추가 kim/team-intro#2

Open • kim (kim) wants to merge 1 commit into main from feature/kim-hobby • less than a minute ago

+1 -0 • No checks

 

 

 kim.md에 취미를 적었어요

 

 

View this pull request on GitHub: https://github.com/kim/team-intro/pull/2

이슈 #1 다음이라 2번

칠한 줄은 kim이 커밋 1개를 main에 합치고 싶다는 뜻이에요.

gh pr list는 열린 PR 목록이에요. #2가 PR 번호예요. 이슈 #1 다음이라 2번이 됐어요. GitHub은 이슈와 PR 번호를 같이 세요. gh pr view 2는 2번 PR의 제목, 상태, 내용을 보여 줘요. 칠한 줄은 kim이 feature/kim-hobby의 커밋 1개를 main에 합치고 싶어 한다는 뜻이에요. 웹에서 보고 싶으면 gh pr view 2 --web을 쳐요.

--merge는 08에서 본 Merge 버튼 세 가지 중 Create a merge commit이에요.

리뷰가 끝난 PR은 gh pr merge로 합쳐요. --merge는 08에서 본 PR Merge 버튼 세 가지 중 Create a merge commit과 같아요. --squash, --rebase 옵션도 있으니 팀이 정한 방식을 골라요. 합친 것은 GitHub의 main이라 내 컴퓨터는 아직 그대로예요. git checkout main, git pull origin main으로 받아 와요. pull 출력은 위쪽 받는 과정을 …로 줄였어요. 오른쪽 git log 맨 위에 Merge pull request #2 커밋이 생겼어요. 화면에 맞추려고 커밋 메시지 뒤를 줄였어요.

브라우저가 안 열려요

github.com/login/device

첫 줄은 설치 직후 자주 나요. 터미널을 껐다 켜면 새로 설치한 gh를 찾아요. 둘째 줄은 로그인 전이라는 뜻이에요. 셋째 줄은 4파트에서 본 권한 에러예요. 넷째 줄은 레포 폴더 밖에서 gh repo view, gh pr list처럼 지금 레포를 쓰는 명령을 쳤을 때예요. pwd로 위치를 보고 레포 폴더로 들어가요. 다섯째 줄은 브랜치를 push하기 전에 gh pr create를 쳤을 때 나오는 질문이에요. Ctrl+C로 멈추고 git push origin 브랜치이름을 친 뒤 다시 해요. 여섯째 줄은 브라우저가 저절로 안 열릴 때예요. 터미널의 코드를 보고 주소를 직접 열어요. 넷째 줄은 실제로 뒤에 (or any of the parent directories): .git이 더 붙어요. 다섯째 줄 질문의 선택지 중 Cancel을 골라도 멈춰요.
