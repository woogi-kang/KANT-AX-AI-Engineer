git log가 길 때 나오는 화면도 같아요. 화면 맨 아래에 : 이나 (END)가 보이면 q예요.

Mac과 Linux에서 git commit --help나 man ls를 치면 터미널 전체가 설명서 화면으로 바뀌어요. 명령을 쳐도 반응이 없어서 멈춘 것처럼 보여요. 이 화면에서는 Space로 다음 쪽, b로 앞 쪽, 슬래시 뒤에 단어를 치고 Enter로 찾고, q로 나가요. 왼쪽 그림은 설명서 화면을 줄여 그린 거예요. 설명서 화면은 이 자료를 만든 환경에서 열 수 없어서 실제 출력을 옮기지 않았어요. Windows Git Bash는 --help가 브라우저로 열려서 이 화면이 나오지 않아요. 02에서 git log 기록이 길 때도 같은 화면이 나와요. 그때도 q예요.

uv는 -h와 --help가 같아요

더 긴 설명은 uv help 명령
예: uv help add

uv --help는 uv에서 쓸 수 있는 명령을 한 줄 설명과 함께 보여 줘요. tools/demo.sh에서 실제로 실행한 출력이고, 아래쪽 명령과 옵션은 …로 줄였어요. 노랗게 칠한 줄은 09에서 쓴 명령이에요. uv는 git과 달리 -h와 --help가 같은 짧은 도움말을 보여 줘요. 더 자세한 설명은 uv help add처럼 help 뒤에 명령 이름을 적어요. 이때는 앞에서 본 설명서 화면처럼 열릴 수 있어서 q로 나와요.

에러는 꾸중이 아니라 힌트예요.

명령 이름을 잘못 치면 git과 uv 모두 비슷한 이름을 찾아 줘요. git stauts에는 status를, uv ad에는 audit과 add를 권해요. 출력은 tools/demo.sh에서 실제로 실행한 결과예요. 끝에는 --help를 쳐 보라는 안내도 있어요. 에러가 나면 지우고 다시 치기 전에 맨 아래 몇 줄을 소리 내어 읽어 봐요. 위 화살표로 앞 명령을 불러와 고치면 빨라요.
