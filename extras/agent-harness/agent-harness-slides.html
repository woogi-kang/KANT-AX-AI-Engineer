AI를 잘 쓰는 방법은 다듬는 범위가 점점 넓어지는 쪽으로 바뀌어 왔어요. 처음에는 질문 한 문장을 다듬었어요. 그런데 모델이 모르는 정보는 아무리 잘 물어도 답할 수 없었어요. 그래서 모델에게 보여 줄 자료를 고르는 컨텍스트로 넘어갔어요. 자료를 잘 줘도 한 번 답하면 끝이라, 모델이 도구를 쓰며 스스로 반복하는 루프가 나왔어요. 루프가 길어지자 길을 잃는 일이 생겨서, 단계와 갈림길을 미리 그려 두는 그래프가 쓰여요. 이 순서는 연도보다 다듬는 범위가 넓어진 순서예요. 그래프 도구인 LangGraph는 2024년부터 있었어요. 2026년에는 이 넷을 묶어 하네스 엔지니어링이라고 불러요.

부딪힌 벽

코드를 직접 붙여 넣지 않으면 모델은 main.py를 볼 수 없어요. 다른 파일, 실행 결과, 팀의 규칙도 몰라요.

잘 묻는 기술은 지금도 쓸모 있어요. 다만 그것만으로는 모자라요.

프롬프트 엔지니어링은 질문 한 문장을 다듬는 일이에요. 짧은 부탁을 역할, 할 일, 답 모양이 분명한 부탁으로 바꾸면 답이 좋아져요. 코드를 붙여 넣으면 더 좋아져요. 그런데 붙여 넣은 것 말고는 모델이 아무것도 몰라요. 프로젝트의 다른 파일도, 실행 결과도, 팀이 정한 규칙도 모르죠. 앞에서 도구 없이 부탁했을 때 명령을 글로만 적고 끝난 것도 같은 벽이에요. 이 벽 때문에 무엇을 보여 줄지를 다듬는 쪽으로 관심이 옮겨 갔어요.

권한: 무엇을 묻고 무엇을 바로 할지 정해요

manual

도구를 쓸 때마다 물어요

acceptEdits

파일 고치기는 바로, 명령은 물어요

plan

읽기만 하고 계획을 세워 보여 줘요

auto

안전해 보이는 일은 바로, 위험하면 멈춰요

bypassPermissions

묻지 않아요. 격리된 곳에서만 써요

Shift+Tab

으로 대화 중에 모드를 바꿔요

.claude/settings.json

{

"permissions": {

"allow": ["Bash(uv run *)"],

"deny": ["Read(./.env)", "Bash(rm -rf *)"]

}

}

← 묻지 않고 실행

deny에 적은 일은 모드와 상관없이 막혀요. 1파트에서 본 "승인이 필요해요"는 allow에 없던 python3 main.py가 걸린 거예요.

권한은 무엇을 묻고 무엇을 바로 할지 정하는 장치예요. 처음엔 도구를 쓸 때마다 물어요. 파일 고치기를 믿을 만하면 acceptEdits로, 먼저 계획만 보고 싶으면 plan으로 바꿔요. auto는 안전해 보이는 일은 바로 하고 위험해 보이면 멈춰요. bypassPermissions는 아무것도 묻지 않아서 컨테이너처럼 격리된 곳에서만 써요. 대화 중에는 Shift+Tab으로 모드를 바꿔요. 자주 쓰는 명령은 settings.json의 allow에, 절대 안 될 일은 deny에 적어요. 1파트 실행이 막힌 것도 allow에 uv run만 있어서였어요.
