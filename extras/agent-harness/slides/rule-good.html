3 · 규칙과 컨텍스트

규칙은 맞았는지 확인할 수 있게 써요

- 코드를 깔끔하게 써 줘

- 테스트를 잘 해 줘

- 위험한 건 하지 마

- 실행은 uv run main.py

- 고친 뒤 uv run main.py로 다시 확인

- 지울 땐 rm -rf 말고 파일을 하나씩

확인할 수 있어요

명령, 파일 이름, 예시처럼 맞았는지 볼 수 있게

자주 틀리는 것만

모델이 이미 잘하는 건 적지 않아요

짧게

길어지면 중요한 줄이 묻혀요. 긴 절차는 스킬로

이 수업 자료 레포의 CLAUDE.md에는 수업 규칙이 모여 있어요. 덱 디자인 절차처럼 긴 내용은 tools/DESIGN.md로 떼어 두고, 덱을 만들 때만 읽게 했어요.

세 번째 줄 같은 금지는 규칙만으로는 약해요. 4파트의 훅으로 막아요.

규칙은 맞았는지 확인할 수 있게 써요. 깔끔하게, 잘, 위험한 것 같은 말은 사람마다 뜻이 달라서 모델도 제멋대로 읽어요. 명령, 파일 이름, 예시를 적으면 지켰는지 바로 보여요. 모델이 이미 잘하는 것은 적지 않고, 자주 틀리는 것만 적어요. 파일이 길어지면 중요한 줄이 묻히니, 가끔 쓰는 긴 절차는 5파트의 스킬로 떼어 내요. 이 레포도 덱 디자인 절차를 tools/DESIGN.md로 떼어 두었어요. 지우지 말라는 규칙은 모델이 잊을 수도 있어서, 꼭 막아야 하는 일은 훅으로 막아요.
